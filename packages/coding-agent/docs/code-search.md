# 语义代码搜索

Pi 内置 `code_search` 工具。它能按“意思”找代码，适合不知道文件名、函数名和准确关键词时使用。

例如：

```text
用户登录流程是怎么实现的
模型配置从哪里加载并注册
技能如何被发现、解析和加入提示词
```

实现结构和关键决策见 [code_search 架构与关键决策](code-search-architecture.md)。

## 什么时候使用

按下面的顺序选择工具：

1. 当前上下文已经足够：直接回答，不搜索。
2. 已知准确文件路径：使用 `read`。
3. 已知函数名、类名、报错、配置键或准确文字：使用内置 `grep`。
4. 路径、符号和关键词都不知道，只知道想找的功能或行为：使用 `code_search`。

例如“API Key 在哪里”属于配置位置问题，通常应先查文档或用 `grep` 搜索 `auth.json`、`API_KEY` 等准确文字，不应先启动语义索引。

`code_search` 是可选加速器，不是完成任务的必要条件。它未就绪或失败时，应立即改用内置 `grep`，不要等待、连续重试，也不要通过 Bash 运行 `rg`。

内置 `grep` 默认开启。如果用户在 `/tools` 中主动关闭它，精确内容搜索就视为不可用；Pi 不会通过 Bash `rg` 绕过这个开关。

## 搜索结果怎么用

首轮默认返回 6 条。先检查结果能否组成“定义 → 加载或注册 → 调用或消费”的完整证据链：

- 证据完整：用 `grep` 核对准确符号，再用 `read` 小范围读取相关代码。
- 证据不足：换一种完整意图再次搜索，或把 `max_results` 依次增加到 12、20。
- 工具不可用：立即改用内置 `grep`。

不要一开始就返回大量结果。结果越多，模型需要读取的内容越多，也越浪费 token。

## 第一次使用

只需执行一次：

```powershell
npm install -g @mixedbread/mgrep
mgrep login
```

`mgrep login` 会打开浏览器，通常需要约 1–2 分钟，不需要另外填写 API Key。

在 `/tools` 中开启 `code_search` 时，Pi 会显示安装、登录、上传范围和后台索引提示。

## 后台索引

第一次真正调用 `code_search` 时，Pi 会启动 mgrep watcher 建立索引。

- 当前调用最多在前台等待 2 秒。
- 2 秒内未完成：索引留在后台继续，本次任务立即改用 `grep`。
- 后台索引完成后：后续真正需要语义搜索的任务可以直接复用。
- Pi 退出或扩展重载时：watcher 自动停止。

单次语义查询最多等待 15 秒。超过后立即停止，并在本次会话中避免继续依赖失败的 mgrep。

## 索引范围

`code_search` 优先索引整个项目，以保留跨目录关系。默认安全上限是 5000 个文件，可用 `MGREP_MAX_FILE_COUNT` 调整。

如果整个项目超过上限：

- 本次明确提供了更小的 `path`：自动尝试索引该目录。
- 没有提供 `path`：停止 mgrep，改用内置 `grep`。
- 指定目录仍超限：记录该范围，本次 Pi 会话不再重复尝试。

如果 `path` 是文件，会索引它的父目录，但只返回该文件中的结果。

## 隐私

mgrep 会把未被忽略的项目文件同步到 Mixedbread。它遵守 `.gitignore` 和 `.mgrepignore`，单个文件默认不超过 1 MB；Pi 默认最多同步 5000 个文件。

请把 `.env`、密钥和其他敏感文件写入 `.gitignore` 或 `.mgrepignore`。`code_search` 只允许访问当前项目内部路径。
