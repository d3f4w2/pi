# 工具发现与工具预算架构

本文记录 `tool_search` 的职责、运行流程和关键决策。使用方法见 [tool-discovery.md](tool-discovery.md)。

## 要解决的问题

工具越多，模型每一轮都要阅读的工具名称、说明和参数就越多。即使这些工具没有被调用，它们也会占用上下文，并增加选错工具的概率。

本功能把“用户允许使用哪些工具”和“这一轮给模型看哪些工具”分开：

- **允许工具池**：用户在 `/tools` 中打开的工具，保存到配置文件。
- **当前工具集**：这一轮真正提供给模型的工具。
- **按需工具**：默认不出现在当前工具集，需要时由 `tool_search` 临时加载。

## 设计目标

- 核心读写和执行能力始终可用，不破坏现有扩展。
- 低频工具按需加载，减少模型每轮接收的工具定义。
- 一次最多加载 2 个按需工具，不让工具列表不断增长。
- 用户关闭 `tool_search` 后恢复旧行为：所有允许工具直接可用。
- 搜索无结果或内部失败时快速返回，不重试、不阻塞主任务。
- `/tools` 的选择继续跨会话保存。

## 非目标

- 不让 `tool_search` 执行其他工具。
- 不根据搜索结果永久修改用户的 `/tools` 选择。
- 不隐藏没有明确声明为按需加载的第三方工具。
- 第一版不做向量索引、外部服务或模型二次调用。

## 运行流程

```text
Pi 启动
  ↓
读取 tool-preferences.json
  ↓
得到“允许工具池”
  ↓
tool_search 是否允许使用？
  ├─ 否：当前工具集 = 全部允许工具
  └─ 是：当前工具集 = 常驻工具 + tool_search
                         ↓
                tool_search("网页资料")
                         ↓
                本地评分并取前 2 个
                         ↓
        当前工具集 = 常驻工具 + tool_search + web_search + web_fetch
                         ↓
                下一轮模型可调用它们
```

再次调用 `tool_search` 会替换上一次临时加载的工具，不会累积。

## 工具发现元数据

只有明确提供 `discovery` 元数据的工具才属于按需工具：

```ts
discovery: {
  keywords: ["网页", "联网", "资料", "search web"],
}
```

未提供该字段的工具保持常驻。这条规则保护核心工具、用户扩展和依赖工具存在的后台流程。

第一版适合按需加载的内置工具：

- `ast_grep`
- `code_search`
- `verify`
- `web_search`
- `web_fetch`

`read`、`bash`、`edit`、`write`、`grep`、`lsp` 和 `tool_search` 保持常驻。

## 搜索与预算

搜索完全在本地完成，不调用模型和网络。评分信号按优先级排列：

1. 工具名完全匹配。
2. 工具名包含查询。
3. 中文关键词或英文词与工具关键词匹配。
4. 查询与工具简介、使用提示匹配。

只有达到最低分，并且与最高分结果足够接近的工具才会入选，最多 2 个。`2` 是上限，不是必须凑满的数量。输出只包含名称和简短中文说明。

工具可以声明一个配套工具。例如 `web_search` 找到链接后经常需要 `web_fetch` 读取正文，因此前者命中时会在预算允许且用户没有关闭后者的情况下，一起加载。配套关系不会绕过用户开关。

预算限制的是“临时加载的按需工具数量”，不是所有工具总数。这样既减少低频工具的提示词成本，又不会为了追求一个很小的固定总数而破坏现有能力。

## 文件职责

| 文件 | 职责 |
|---|---|
| `core/extensions/types.ts` | 定义工具发现元数据。 |
| `core/agent-session.ts` | 把发现元数据暴露给扩展运行时。 |
| `extensions/tools/discovery.ts` | 本地评分、预算裁剪和当前工具集计算。 |
| `extensions/tools/index.ts` | 注册 `tool_search`，维护允许工具池和临时工具。 |
| `extensions/tools/ui.ts` | 显示用户允许状态和简短中文说明。 |
| 各内置工具入口 | 声明自己的发现关键词。 |

## 关键决策

### ADR-001：允许状态与当前状态分离

决定：`/tools` 管理允许工具池，`pi.setActiveTools()` 只管理当前工具集。

原因：临时加载是运行时优化，不应被误写成用户偏好。否则一次搜索会让工具永久打开，或者一次隐藏会让用户误以为工具被关闭。

### ADR-002：只有主动声明的工具按需加载

决定：没有 `discovery` 元数据的工具保持常驻。

原因：第三方扩展可能在后台事件或系统提示中依赖自己的工具。默认隐藏会造成无法预料的兼容性问题。

### ADR-003：一次最多加载 2 个工具

决定：每次搜索取前 2 个，并替换旧结果。

原因：通常一个任务只需要一个能力，网页研究等场景可能需要一对配套工具。超过 2 个的收益很小，但会重新扩大上下文和选择空间。

### ADR-004：关闭 tool_search 即恢复全部允许工具

决定：用户关闭 `tool_search` 后不再应用动态隐藏。

原因：发现机制是优化层，不是基础依赖。它不可用或用户不喜欢时，原有工具仍应正常工作。

### ADR-005：本地轻量匹配，不建立语义索引

决定：使用工具名、关键词、简介和提示进行确定性评分。

原因：工具数量通常很少。向量索引或额外模型调用会增加延迟、token 和失败点，收益不足。

### ADR-006：发现只加载，不执行

决定：`tool_search` 只更新下一轮工具定义并返回结果。

原因：真正执行仍要经过目标工具自己的参数校验和权限边界，职责清楚，也便于审计。

### ADR-007：弱匹配不用于填满预算

决定：候选工具必须同时通过绝对最低分和相对最高分门槛。配套工具由明确元数据补入，不依赖模糊文字重合。

原因：预算是安全上限。如果为了凑满两个而返回弱相关工具，会增加 token，并让模型误用完全无关的能力。

## 失败处理

- 查询为空：立即返回简短提示。
- 没有匹配：不改变当前工具集，提示改用更具体的能力描述。
- 已匹配工具被用户关闭：不返回、不加载。
- 内部状态异常：保留常驻工具，返回短错误，不自动重试。
- `tool_search` 被关闭：全部允许工具直接可用。
- 同一轮代理最多为连续空结果保留两个联网搜索名额；名额在请求发出前占用，因此并发调用也不能穿透预算。达到上限后，`web_search` 引导使用已加载的 `web_fetch` 或直接说明没有找到。
- 重定向、内容限制和读取失败需要丢弃响应流；流清理错误会被隔离，普通网络失败不得触发 Pi 的未捕获异常。

## 测试要求

- 中文和英文查询能找到正确工具。
- “最新版本”只加载联网工具，不会因为“搜索”二字误加载代码搜索工具。
- 强命中可以带入明确声明且仍被用户允许的配套工具。
- 精确名称优先于普通关键词。
- 结果不超过 2 个且排序稳定。
- 关闭的工具不会被发现。
- 新搜索替换旧搜索结果。
- `/tools` 保存的是允许状态，不是临时状态。
- 关闭 `tool_search` 后全部允许工具恢复。
- 发现元数据能从工具定义传到扩展运行时。
