# ast_grep 架构与关键决策

## 目标

在普通文字搜索和 LSP 之间补一层“代码结构搜索”：准确识别语法节点，同时保持速度快、输出短、失败不拖任务。

## 第一性原理

代码搜索最终要解决五件事：

```text
用户描述结构
    ↓
限制搜索范围
    ↓
把源码解析成语法树
    ↓
在语法树中匹配结构
    ↓
只返回位置和一行摘要
```

普通 `grep` 只比较字符，因此注释和字符串也可能命中。`ast_grep` 先解析语法树，再比较节点，所以结果更准确。

## 模块结构

```text
extensions/ast-grep/
├── index.ts   工具注册、参数和模型使用规则
├── search.ts  路径保护、文件扫描、解析、匹配和结果压缩
└── types.ts   语言、请求、结果和详情类型
```

调用链：

```text
模型调用 ast_grep
    ↓
index.ts 校验参数，语言默认 auto
    ↓
search.ts 校验项目边界和资源预算
    ↓
按文件扩展名选择解析器并匹配 AST
    ↓
少量结果返回代码，大量结果按文件压缩位置
```

## ADR-012：使用官方 NAPI，不经过 shell

决定：固定使用官方 `@ast-grep/napi`，直接在 Node.js 进程中解析代码。

原因：

- 不依赖 Git Bash、PowerShell、WSL 或系统 PATH。
- 用户不需要额外安装、登录或配置。
- 避免命令拼接和 shell 转义问题。
- 官方 `findAll` 在原生层完成结构匹配，减少 JavaScript 与原生层的往返。

代价：当前只开放 NAPI 内置的 JavaScript、TypeScript、TSX、HTML 和 CSS。新增语言时应增加独立语言适配器，不改变工具协议。

## ADR-013：第一版只读

决定：只实现搜索，不实现结构替换。

原因：搜索失败只会少返回结果；替换失败会修改大量文件。结构修改应单独设计预览、确认、项目边界、冲突检测和回滚机制，不能混入只读搜索。

## ADR-014：资源预算优先于完全扫描

固定预算：

- 结果默认 100 条，用户明确需要全部时最多 1000 条。
- 搜索范围最多 5000 个文件。
- 单文件最多 1 MB。
- 总运行时间最多 15 秒。
- 每批并行解析 4 个文件。
- 小结果每条代码摘要最多 180 个字符。
- 大结果按文件合并位置，最终输出最多约 30000 个字符。

达到预算后停止或要求缩小范围。可选工具失败时，模型立即改用 `grep` 和 `read`，不得反复重试。

## ADR-015：自动语言与自适应输出

决定：`language` 可以省略，默认使用 `auto`。一次遍历同时识别 JavaScript、TypeScript、TSX、HTML 和 CSS，不再让模型按语言分别调用。

输出规则：

- 20 条以内：返回 `file:line:column + 代码片段`，方便立即理解。
- 超过 20 条：按文件合并为位置列表，不重复路径和代码片段。
- 用户明确要求“全部”时：一次调用 `max_results=1000`；只有仍超限时才缩小 `path`。

同时在工具规则中禁止为了枚举文件而调用 shell、环境变量或目录列表。文件发现属于 `ast_grep` 自己的职责。

## 工具分工

| 需求 | 工具 |
| --- | --- |
| 已知准确文字、报错、配置键 | `grep` |
| 已知代码结构，如某类函数调用 | `ast_grep` |
| 定义、引用、类型、诊断、重命名 | `lsp` |
| 不知道路径和关键词，只知道功能意思 | `code_search` |
| 已知文件，需要看附近实现 | `read` |

这个分工避免所有问题都走昂贵的语义搜索，也避免为了简单文字查询启动语法解析。

## 扩展新语言

新增语言只需要：

1. 提供 ast-grep 语言解析器。
2. 在 `types.ts` 增加语言名。
3. 在 `search.ts` 增加语言与文件扩展名映射。
4. 增加“真实代码命中、注释和字符串不命中”的回归测试。

工具名、参数和紧凑输出格式保持不变。
