# Todo 长任务状态架构

## 目标

让主代理在长任务中始终知道：总目标是什么、当前做哪一项、哪些已经验证、哪些被阻塞、下一步是什么。状态必须能跨会话恢复、分支导航和上下文压缩，同时不持续占用大量 Token。

## 功能要求

- 一个会话维护一份分阶段任务状态。
- 每个阶段和任务使用稳定 ID，修改时不依赖完整文字匹配。
- 同一时刻最多只有一个 `in_progress` 任务。
- 当前任务关闭后，自动推进到下一项待办。
- 完成任务必须提供简短验证证据。
- 每次修改携带 `expected_revision`，旧上下文不能覆盖新状态。
- 每次成功修改作为自定义会话条目持久化。
- 恢复会话或切换分支时，从当前分支的最后一个有效快照重建。
- TUI 只显示紧凑进度；模型只接收当前任务和有限数量的未完成任务。
- 用户可用 `/tasks` 查看完整状态。

## 非功能要求

- 不调用模型、网络、Shell 或后台进程。
- 最多 8 个阶段、100 个任务，标题和证据都有长度上限。
- 读取损坏或未知版本的快照时继续寻找更早的有效快照；全部无效时回退到空状态。
- `view` 不写入会话；失败的修改不产生半成品状态。
- 上下文注入有固定条数和字符预算，任务越多也不会无限增长。

## 数据结构

```text
TaskLedgerState
├── schemaVersion: 1
├── revision
├── nextPhaseNumber
├── nextTaskNumber
└── phases[]
    ├── id: pN
    ├── title
    └── tasks[]
        ├── id: tN
        ├── title
        ├── status: pending | in_progress | completed | blocked | abandoned
        ├── evidence?   完成证据
        └── blocker?    阻塞原因
```

## 数据流

```text
todo 工具调用
    |
    v
读取当前分支最后一个 task-ledger-v1 快照
    |
    v
检查 expected_revision
    | 不一致 -----------------> 标准工具错误，不写入
    v
在副本上执行一次状态转换
    |
    v
校验上限与单一进行中任务
    |
    v
revision + 1
    |
    +--> pi.appendEntry() 持久化完整快照
    +--> 工具结果返回完整状态
    +--> TUI 更新紧凑任务组件
```

会话启动、恢复或树分支切换时，扩展重新扫描当前分支。`before_agent_start` 只在本轮系统提示中追加当前任务、阻塞项和最多若干个待办，不写入消息历史；已完成任务只保留计数，因此压缩后仍能继续，Token 也保持有界。

## 操作

| 操作 | 作用 |
|---|---|
| `set_plan` | 用阶段和任务替换当前计划，自动分配稳定 ID |
| `add` | 向已有或新阶段追加任务 |
| `start` | 指定唯一进行中任务 |
| `complete` | 带证据完成任务 |
| `block` / `unblock` | 设置或解除阻塞 |
| `abandon` | 明确放弃任务 |
| `reopen` | 重新打开已关闭任务并清理旧证据 |
| `remove` | 删除单个任务 |
| `clear` | 清空计划但保留单调 ID 计数器 |
| `view` | 只读查看，不增加 revision |

除 `view` 外，所有操作都要求 `expected_revision`。第一次建立计划使用 `0`。

## 超过 Oh My Pi 的关键点

Oh My Pi 当前 todo 通过任务完整文本定位，并把完成状态作为主要进度信息。本实现增加三项一致性保障：

1. 稳定 ID：重名任务和标题变化不会误命中。
2. 乐观版本：并行工具调用或旧上下文不能覆盖新状态。
3. 完成证据：`complete` 必须说明通过了什么检查、产生了什么提交或观察到了什么结果。

## 失败模式

| 问题 | 处理 |
|---|---|
| revision 过期 | 拒绝修改，要求先 `view` |
| 任务 ID 不存在 | 拒绝修改，不写快照 |
| 完成时缺少证据 | 拒绝修改 |
| 阻塞时缺少原因 | 拒绝修改 |
| 快照损坏或版本未知 | 忽略该快照，继续向前查找有效快照 |
| 会话分支切换 | 从新分支重新加载，不沿用旧分支内存状态 |
| 任务很多 | 模型注入和 TUI 只显示有界摘要，完整状态仅在工具结果和 `/tasks` 中显示 |

## 安全与成本

- 自定义条目不进入模型上下文，避免重复发送完整计划。
- 只有 `before_agent_start` 的有界摘要进入上下文。
- 状态转换纯内存完成，无外部副作用；持久化失败时工具调用失败。
- 标题、证据和阻塞原因不会作为命令执行。

## 验证

- 状态机单元测试：初始化、自动推进、阻塞、重开、删除和清空。
- revision 冲突和失败原子性测试。
- 完成证据必填测试。
- 会话分支快照恢复和损坏快照降级测试。
- 扩展注册、持久化、上下文注入、组件更新和 `/tasks` 测试。
- 全项目类型、格式和相关扩展回归检查。
