# 工具管理架构与关键决策

本文记录 `/tools` 的状态持久化结构和关键取舍。使用方法见 [tools.md](tools.md)。

## 设计目标

- 内置工具和扩展工具使用同一套开关逻辑。
- 用户选择在重启后自动恢复。
- 用户允许状态与模型当前看到的工具分开管理。
- 新增工具不会因为旧配置而永久隐藏。
- 多个 Pi 进程保存时不会互相覆盖无关选择。
- 配置读取失败不能阻塞代理启动。

## 文件职责

| 文件 | 职责 |
|---|---|
| `extensions/tools/index.ts` | 注册 `/tools`、应用启动配置、记录本次界面的开关变化。 |
| `extensions/tools/discovery.ts` | 按能力查找低频工具，并计算当前实际提供给模型的工具。 |
| `extensions/tools/storage.ts` | 读取、合并并加锁保存工具偏好。 |
| `extensions/tools/ui.ts` | 显示工具列表，处理上下和左右键。 |
| `test/tools-extension.test.ts` | 验证启动恢复、界面操作和保存调用。 |
| `test/tools-storage.test.ts` | 验证偏好合并、状态迁移和新增工具默认值。 |

## 数据结构

```json
{
  "enabledTools": ["code_search", "grep"],
  "disabledTools": ["find", "ls"]
}
```

配置保存在 `~/.pi/agent/tool-preferences.json`。

这里不保存完整活动工具列表，而是保存用户覆盖项。启动时：

```text
当前默认工具
        ↓
移除 disabledTools
        ↓
加入当前仍然存在的 enabledTools
        ↓
得到用户允许工具池
        ↓
由 tool_search 计算当前工具集
```

未知工具不会加入当前会话，但名称继续保存在配置中，方便扩展重新安装后恢复。

## 保存流程

进入 `/tools` 时记录初始允许状态。用户按左右键会立即更新允许工具池和当前会话；按 Enter 或 Esc 完成后，只计算真正发生变化的用户选择并保存。临时发现的工具不会写入偏好文件。

存储使用文件锁执行“读取最新配置 → 合并本次变化 → 写回”。因此两个 Pi 进程分别修改不同工具时，后保存的进程不会用旧的完整列表覆盖另一个进程的修改。

## 关键决策

### ADR-001：保存覆盖项，不保存完整列表

决定：分别保存 `enabledTools` 和 `disabledTools`。

原因：完整列表无法区分“用户关闭”和“当时还不存在”。软件升级增加新工具后，旧完整列表会让新工具永远处于关闭状态。

### ADR-002：所有工具按名称统一处理

决定：不区分内置工具、内置扩展工具和用户扩展工具。

原因：对用户来说它们都是可调用能力。按名称保存可以避免为每种来源维护不同配置结构。

### ADR-003：完成界面时保存

决定：左右键立即改变当前会话，Enter 或 Esc 离开界面时统一持久化差异。

原因：减少磁盘写入，并把一次界面操作视为一个完整事务。

### ADR-004：配置失败不阻塞代理

决定：启动读取失败时保留默认工具；保存失败时保留当前会话状态并显示警告。

原因：工具偏好是便利功能，不能因为配置文件损坏或临时锁冲突导致 Pi 无法工作。

### ADR-005：允许状态与当前状态分离

决定：`/tools` 只管理用户允许状态；`tool_search` 可以临时缩小或扩大模型当前看到的工具，但不修改保存的偏好。

原因：按需加载是运行时优化，不是用户开关。把两者混在一起会让临时隐藏被误认为永久关闭。

完整的工具预算、搜索评分和失败回退决策见 [工具发现架构](tool-discovery-architecture.md)。

## 测试要求

- 空配置返回空覆盖项。
- 开关变化会在启用和禁用集合之间移动。
- 启动时正确恢复用户选择。
- 新增默认工具不会被旧配置删除。
- 未安装工具的记录不会丢失。
- `/tools` 关闭后只保存真正变化的工具。
- 临时发现不会改变用户保存的开关。
- 关闭 `tool_search` 后恢复全部允许工具。
- 保存失败不会撤销当前会话状态。
