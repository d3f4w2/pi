# 工具执行保护

Pi 会统一处理工具异常、超时、取消和连续失败。单个工具出问题时，主代理仍能改用其他方法继续任务。

默认包含两层保护：

### 相同调用保护

1. 第一次调用正常执行。
2. 第二次相同调用仍然执行，给瞬时问题一次恢复机会。
3. 如果两次错误也相同，第三次调用不会执行底层工具。
4. 代理会收到明确提示：修改参数、换工具，或者说明当前阻塞原因。
5. 如果代理无视提示，再次重复同一个被阻止的调用，当前自动运行会结束，避免继续消耗 Token。

### 工具熔断

即使参数不同，同一个工具连续执行失败 3 次也会暂时停用 30 秒：

1. 熔断期间不会再次执行底层工具。
2. 冷却结束后只放行一次测试调用。
3. 测试成功就恢复；失败则重新冷却。
4. 用户开始一个新任务时立即清空熔断状态。

默认情况下，单次工具调用最长等待 180 秒。超时会停止等待并要求工具取消工作，主代理随后可以继续。设置 `timeoutMs: 0` 可以关闭统一超时。

以下情况会重新允许调用：

- 参数发生变化
- 返回了不同错误
- 任意工具有一次调用成功
- 用户发送新消息
- 开始新的代理运行

用户中止和取消不计入失败次数。工具返回的异常会先隐藏常见密钥、删除控制字符并限制长度，再交给模型，避免错误信息浪费 Token 或泄漏凭据。

被阻止的调用仍然生成标准工具结果，因此不会破坏模型接口的调用顺序。输入 `/doctor` 可以查看当前被熔断的工具。

## 配置

```json
{
  "toolFailureGuard": {
    "enabled": true,
    "repeatLimit": 2,
    "consecutiveLimit": 3,
    "cooldownMs": 30000,
    "timeoutMs": 180000
  }
}
```

通常不需要修改默认值。关闭 `enabled` 后，四项通用保护都会关闭，但各个工具自己的错误处理仍然有效。

工具如果忽略取消信号，JavaScript 无法强制结束它。Pi 会停止等待、忽略迟到的进度并持续观察最终结果，确保迟到的失败不会变成未处理异常；工具作者仍应正确响应 `AbortSignal`。
