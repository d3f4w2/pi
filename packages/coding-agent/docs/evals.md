# 测试与 Agent 能力评测

两个入口不能混用：

```text
/tests  → 直接运行代码测试，不调用模型
/evals  → 启动全新 Agent 完成真实任务，消耗模型 token
```

## `/tests`：代码回归测试

用来防止已经修好的产品 Bug 再次出现：

```text
回归测试 · 防止修好的问题再次出现

运行最近案例
选择其他案例
```

它只运行选择的测试文件，不调用模型，不扫描整个仓库，也不会扩大为全仓测试。

## `/evals`：真实 Agent 能力评测

```text
Agent 能力评测 · 启动全新 Agent，并消耗模型额度

运行全部 5 个能力案例
选择一个能力案例
查看最近结果
```

每个案例都在独立临时项目中启动一个全新 Agent。Agent 自己理解任务、查找代码、修改和验证；结束后系统才写入隐藏测试进行客观验收。临时项目随后删除，不影响当前仓库。

第一版每类只有一个案例：代码定位、Bug 修复、修改后验证、失败后恢复、范围与 token 控制。每个案例最长两分钟，运行前必须确认会消耗当前模型额度。运行时会在输入框上方持续显示当前阶段、耗时、工具调用次数以及最近一次工具输入或结果摘要。

完成后会在聊天记录中生成一张本地报告卡片。默认只显示通过数量、总耗时、token 和工具次数；按 `Ctrl+O` 可以展开或收起。展开后能看到按时间排序的准备、启动、工具调用、Agent 工作、隐藏验收和清理链路，以及每一步耗时、短输入、短结果、Agent 最终回答、延迟分解和 token 分解。报告不会发送给模型，因此查看详情不会增加模型 token。

每次完成案例后，系统会自动找到同一案例的上一次结果，并在展开报告中展示结果、模型配置、总耗时、输出与总 token、错误次数和工具构成的前后变化。工具构成分成“上次”和“本次”两行，本次只给发生变化的工具标注增减值；完整时间顺序仍在执行链路中。这里只显示原始数值与差值，不自动判断提升或退步；第一次运行该案例时会明确显示暂无历史结果。不需要新的命令或手动保存基线。

效率预算限制的是 Agent 输出 token 和工具调用次数。系统提示与工具说明产生的输入 token 仍会如实记录，但不会单独导致案例失败。

隔离运行设计见 [ADR 0028](adr/0028-isolated-agent-capability-evaluation.md)，可展开报告设计见 [ADR 0029](adr/0029-expandable-agent-evaluation-traces.md)。

## `/evals-dev`：评测器内部自检

它检查评测器的固定统计、报告和基线逻辑，不衡量 Agent 能力。普通用户不需要使用。

对应的直接命令保留给脚本和开发调试：

```text
/evals-dev run
/evals-dev latest
/evals-dev baseline
/evals-dev compare
/evals-dev failures
```

开发评测器时的使用顺序：

1. 运行 `/evals-dev run`。
2. 确认 10 个离线案例通过。
3. 运行 `/evals-dev baseline` 保存当前报告。
4. 修改代码并再次运行 `/evals-dev run`。
5. 运行 `/evals-dev compare` 查看差异。

报告比较成功率、Token、P50/P95 耗时、工具调用、错误和重试。报告保存在 `~/.pi/agent/evals/`。

## 边界

- 不调用模型。
- 不联网。
- 不读取 API Key、源码正文、提示词、路径或工具输入。
- 只验证评测器的本地数据和比较链路。
- 10 个案例全部通过不代表代理能力已经提高，也不能作为自动推广依据。

设计决策见 [ADR 0022](adr/0022-local-deterministic-evaluation-foundation.md) 和 [ADR 0027](adr/0027-separate-regression-tests-from-evaluator-tools.md)。

## 从真实错误制作回归测试

制作代码回归案例不在 `/tests` 菜单中手动启动。只有系统观察到“失败后修改代码，并且后续验证通过”，才会显示脱敏摘要：

```text
是否制作最小回归测试？

允许制作
拒绝
不再提示此类错误
```

选择“允许制作”后，系统才会临时开启一次制题能力。制题期间不能读取文件、联网或执行其他工具，只能使用对话里已经存在的信息。

生成完成后会显示测试路径、复现步骤、修复前后表现和完整文件内容。只有再次确认，测试文件才会写入当前项目。

二次确认前还有一个本地质量门。测试必须包含真实断言，并引用项目模块、包、CLI 或 Go 被测调用。只在测试文件里定义一个假函数再断言的“自证型测试”会直接拒绝，不会写入项目。

限制：

- 最多创建两个新测试文件，总内容不超过 4,000 个字符。
- 不能覆盖已有文件。
- 只能写入明显的测试路径或测试文件名。
- 检测到密钥、私人密钥、用户绝对路径或危险控制字符时直接拒绝。
- 任一步骤失败会回滚本轮已经创建的文件。
- 拒绝时不保存候选；无确认界面时默认拒绝。
- 可以永久关闭同类错误提示，但不能永久自动批准制题。

批准记录保存在 `~/.pi/agent/evals/cases/`，只保存来源、文件路径和内容哈希，不复制测试正文。测试正文跟随项目进入 Git 审查。

设计决策见 [ADR 0023](adr/0023-user-approved-regression-case-capture.md)。

质量门设计见 [ADR 0026](adr/0026-evidence-gated-regression-test-quality.md)。
