# 本地评测

普通使用不需要记下面这些命令。pi-go 会在真实错误已经恢复后主动询问，用户两次同意才会把它加入测试集。

case 加入后，在 pi-go 内运行 `/evals`，再选择“测试最近案例”或“选择历史案例”。系统只运行对应范围，不会扩大为全仓测试。

`/evals` 是开发者自检入口，用来检查本机评测基础是否工作，并把结果和一个已保存的基线比较。

```text
/evals run
/evals latest
/evals baseline
/evals compare
/evals failures
```

推荐顺序：

1. 运行 `/evals run`。
2. 确认 10 个离线案例通过。
3. 运行 `/evals baseline` 保存当前报告。
4. 修改代码并再次运行 `/evals run`。
5. 运行 `/evals compare` 查看差异。

报告比较成功率、Token、P50/P95 耗时、工具调用、错误和重试。报告保存在 `~/.pi/agent/evals/`。

## 边界

- 不调用模型。
- 不联网。
- 不读取 API Key、源码正文、提示词、路径或工具输入。
- 只验证评测器的本地数据和比较链路。
- 10 个案例全部通过不代表代理能力已经提高，也不能作为自动推广依据。

设计决策见 [ADR 0022](adr/0022-local-deterministic-evaluation-foundation.md)。

## 从真实错误制作回归测试

通常不需要手动运行命令。代理发现一个错误已经被恢复后，会先显示脱敏摘要：

```text
是否制作最小回归测试？

允许制作
拒绝
不再提示此类错误
```

选择“允许制作”后，系统才会临时开启一次制题能力。制题期间不能读取文件、联网或执行其他工具，只能使用对话里已经存在的信息。

生成完成后会显示测试路径、复现步骤、修复前后表现和完整文件内容。只有再次确认，测试文件才会写入当前项目。

限制：

- 最多创建两个新测试文件，总内容不超过 4,000 个字符。
- 不能覆盖已有文件。
- 只能写入明显的测试路径或测试文件名。
- 检测到密钥、私人密钥、用户绝对路径或危险控制字符时直接拒绝。
- 任一步骤失败会回滚本轮已经创建的文件。
- 拒绝时不保存候选；无确认界面时默认拒绝。
- 可以永久关闭同类错误提示，但不能永久自动批准制题。

批准记录保存在 `~/.pi/agent/evals/cases/`，只保存来源、文件路径和内容哈希，不复制测试正文。测试正文跟随项目进入 Git 审查。

设计决策见 [ADR 0023](adr/0023-user-approved-regression-case-capture.md)。
