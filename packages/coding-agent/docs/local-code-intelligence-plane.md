# 本地代码智能平面架构

## 范围

本地代码智能平面由三个互相独立、失败时开放降级的能力组成：

- AST：在同一套语言检测、文件过滤和结构化匹配逻辑上搜索与修改代码。
- LSP：同一项目的多个 pi-go 会话通过本地 IPC 共享语言服务器；共享链路失败时改用会话私有进程。
- Eval：持久 Python/Bun 单元可以调用固定的只读工具集，但不能把解释器变成任意 pi-go 工具入口。

不在范围内：远程 broker、模型调用、扩大自动 LSP 反馈预算、写工具桥接、MCP/ACP 行为变更、沙箱或审批降级。

## 非功能要求

| 方面 | 要求 |
|---|---|
| 隔离 | AST/Edit、LSP 共享和 Eval 工具调用都只能访问当前项目；不同项目不得共享 LSP 状态。 |
| 可靠性 | AST 多文件写入保持预览、版本校验、原子替换和全量回滚；broker 崩溃后私有 LSP 接管。 |
| 性能 | 第二会话 LSP 可用时间比冷启动降低至少 50%；AST 继续遵守文件、大小、结果和时间上限。 |
| 资源 | LSP 使用引用计数和空闲退出；Eval 每单元限制调用数、参数、输出和总时间。 |
| 安全 | IPC 仅使用 Unix socket 或 Windows named pipe；Eval 工具名由宿主白名单决定，不接受递归工具调用。 |
| 可运维性 | LSP 提供协议化健康状态、负缓存和 reload 清理；三部分分别有无模型、无网络专项测试。 |

## 总体结构

```text
ast_grep / ast_edit
        |
        v
共享 LanguageRegistry
  |- @ast-grep/napi 内建语言
  |- 官方动态 tree-sitter 语言包
  `- 受限 Markdown 块级适配器
        |
        +--> 搜索：文件 + 范围 + 捕获组
        `--> 编辑：内存预览 -> 版本复核 -> 原子写入/回滚 -> 语法复核

pi-go 会话 A -----\
                   >-- 本地 pipe/socket --> 项目 LSP broker --> 一个语言服务器
pi-go 会话 B -----/          |
                              `-- 失败/崩溃 --> 会话私有语言服务器

Python pi_tool / Bun piTool
        |
        v
单元请求路由（调用数、超时、递归、AbortSignal）
        |
        v
固定白名单 read / grep / find / ls
        |
        `--> 参数校验 -> 工作区边界 -> 输出上限 -> 不可信网页标记
```

## AST 数据流

`LanguageRegistry` 是搜索和编辑唯一的语言来源。自动模式按扩展名检测；显式语言只允许该语言的文件。单文件扩展名与显式语言冲突时仍按显式语言解析，但目录扫描只收集该语言声明的扩展名。不支持的扩展名在单文件请求中返回一次明确错误；目录自动扫描跳过它。

每个匹配结果保存文件、字节范围、行列范围、完整匹配文本和捕获组。编辑阶段复用同一匹配器和捕获结果生成候选内容。JSON 和 YAML 在生成候选内容后重新解析；任何语法错误都会在写盘前终止整个计划。

Markdown 第一版只承诺标题、围栏代码块和链接的块级结构模式，不声称支持通用 Markdown AST 查询。未支持的模式立即返回错误，不使用文本搜索伪装结构化结果。

## LSP 共享数据流

broker endpoint 由规范化项目根、语言适配器和启动配置的缓存键确定：Windows 使用 `\\.\pipe\pi-go-lsp-*`，Unix 使用临时目录下的本地 socket 并设置为仅当前用户可读写。协议握手必须携带版本、项目根和语言服务器启动配置。

broker 缓存键包含规范化项目根、语言适配器、命令和参数。每个共享服务器记录客户端集合、初始化结果、JSON-RPC 路由、打开文档版本、进程 ID 和失败负缓存。第二个客户端复用初始化结果，不重复启动服务器。

客户端把共享 socket 包装成标准 LSP 流。共享连接不可达、握手失败、初始化失败或运行中断开时，弹性客户端只做一次私有进程接管，并重新打开当前文档。`reload` 同时清除进程内配置状态和 broker 的服务器/失败缓存。关闭一个会话只减少引用；仍有其他引用时不会向真实服务器发送 shutdown。

## Eval 桥梁数据流

解释器与宿主继续使用 JSON 行协议。代码单元执行期间，解释器只能发送 `tool_call` 消息；宿主验证该消息属于当前单元、工具位于固定白名单、调用未递归且预算未耗尽，再调用现有只读工具定义。结果通过 `tool_result` 返回解释器。

默认限制：每单元最多 8 次工具调用、参数 16 KiB、单次工具输出 32 KiB、总输出继续遵守 Eval 的 32 KiB 上限，所有工具调用共享代码单元总超时和 AbortSignal。路径参数在工具执行前解析并校验真实路径仍位于工作区。网页读取保留现有网络防护，并在返回 Eval 前再次添加不可信内容标记。

## 失败模式

| 失败 | 行为 |
|---|---|
| 动态 AST 解析器缺失或注册失败 | 对该语言返回一次明确错误，不回退为文本替换。 |
| AST 候选 JSON/YAML 无效 | 写盘前拒绝整个计划。 |
| AST 预览后文件变化 | 写入任何文件前拒绝整个计划。 |
| AST 中途写入失败 | 逆序恢复所有已写文件并报告回滚失败。 |
| broker 不可达或协议不兼容 | 当前会话直接启动私有 LSP。 |
| 共享服务器初始化失败 | broker 记录有期限的负缓存；客户端回退私有 LSP。 |
| broker 或共享服务器运行中崩溃 | socket 关闭；弹性客户端启动私有 LSP并重试当前操作一次。 |
| Eval 工具越权、递归或路径越界 | 只拒绝该工具调用；代码单元收到可捕获错误。 |
| Eval 单元超时或取消 | 终止解释器，清理未完成工具请求，后续调用按需新建环境。 |
| Python/Bun 缺失 | 遍历固定候选一次后返回安装提示，不安装、不循环重试。 |

## 验证与量化

专项测试分别覆盖 AST、LSP broker 和 Eval bridge。LSP 使用假服务器测量冷启动、共享接入、进程数和失败回退；指标记录写入 `docs/benchmarks/`。测试只创建本地临时文件和进程，不调用模型、真实语言服务器或网络。
