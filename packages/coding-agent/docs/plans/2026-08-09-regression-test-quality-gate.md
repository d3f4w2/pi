# 回归测试质量门实现计划

## 目标

阻止普通预期错误和不触达真实产品代码的自证型测试进入正式回归测试集。

## 步骤

1. 收紧恢复信号。
   - 输出：失败后必须观察到代码修改和明确验证通过。
   - 测试：普通读取失败不触发；完整修复链路触发；取消和未验证不触发。
2. 增加候选静态质量分析。
   - 输出：测试框架、断言、产品引用和拒绝原因。
   - 测试：拒绝本地假实现；接受真实模块、CLI、Python 和 Go 入口。
3. 接入双重审批和持久记录。
   - 输出：无效候选在二次审批前停止；有效候选显示产品触达证据并保存质量字段。
   - 测试：拒绝不写文件；批准记录可追溯；旧记录仍可读取。
4. 更新用户说明并验证。
   - 输出：文档解释“能运行”和“有效”的区别。
   - 测试：专项测试、真实交互初始化和 `npm run check` 通过。

## 不做

- 不让模型给候选打分。
- 不自动修改源码制造红灯。
- 不自动执行候选。
- 不把静态证据描述为完整语义证明。
