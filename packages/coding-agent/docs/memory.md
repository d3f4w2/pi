# 长期记忆

长期记忆让 Agent 跨会话保留少量用户偏好、项目事实、任务经历和已验证方法。它不保存完整聊天，也不会把历史内容当成当前命令。

## 工作方式

```text
用户自然地要求记住
  → 主 Agent 理解内容
  → 调用 memory.remember
  → 确定性代码验证并保存
  → 工具返回真实回执

Agent 在任务中发现可复用经验
  → 调用 memory.propose
  → 保存为候选
  → 任务结束时立即让用户批准、拒绝或稍后处理

用户要求忘记某条记忆
  → Agent 先召回准确 ID
  → 调用 memory.forget
  → 返回真实删除回执
```

系统不再解析“请记住”等固定句式。`memory` 工具对主 Agent 始终可见；Agent 没有得到成功的存储回执时，不能声称已经记住。

## 四类记忆

- 用户：回答风格、语言和长期工作偏好。全局生效，默认属于核心记忆。
- 项目：命令、架构和仓库约定。在当前项目生效，必须绑定项目证据。
- 经历：一次任务中已经确认的结果或失败恢复经验。必须绑定项目证据。
- 方法：经过验证、以后可以复用的工作流程。必须绑定项目证据。

每条记忆使用 `主体 + 属性 + 值` 表示稳定事实。例如：

```text
project.check_command = npm run check
user.response_style = concise
```

这使系统可以识别同一事实的新旧值。新值生效后，旧值保留在历史中，但不会继续参与默认召回。

## 证据和失效

项目、经历和方法记忆最多绑定五个项目文件。推荐同时保存支持事实的精确原文：

```text
AGENTS.md: "Run npm run check before commit."
```

系统会规范化空白并在整个文件中重新定位这段原文。因此，在原文前面增加标题或移动行号不会让记忆失效；原文被删除或改变时，记忆会自动停止使用。

未提供精确原文时会退回整文件摘要，这种模式下任何文件内容变化都会让记忆失效。

分支记录为来源信息，但不会默认隔离同一仓库的记忆。是否可用由当前证据决定，避免切换分支后正确的项目规则无故消失。

## 召回和消耗

新会话首轮最多加载三条核心用户偏好，并为当前任务相关的项目记忆保留空间。后续需要更多历史时，Agent 调用 `memory.recall`。

召回在本地完成，综合以下信号：

- 主体、属性和值的精确匹配；
- 短语、英文词、中文字符和片段；
- 文件路径和证据原文；
- 可信度、重要性和历史帮助率。

每次最多返回五条、自动上下文最多约 1,500 字。不调用额外模型，不依赖网络或向量服务。召回失败时普通任务继续运行。

Agent 使用记忆后可以记录 `adopted`、`helpful`、`harmful` 或 `neutral` 反馈。这些数据用于排序和专项测评，不会根据单次失败自动删除事实。

## 用户管理

输入 `/memory` 可以查看：

- 待确认：Agent 提出的候选；
- 当前记忆：现在可以被召回的记录；
- 历史：已替代、已失效或已拒绝的记录。

Agent 每个任务最多提出一条候选。任务结束时会直接显示候选并让用户批准、拒绝或稍后处理；稍后仍可在 `/memory` 中处理。所有记录都可以彻底删除，也可以直接用自然语言要求 Agent 忘记。界面会显示事实、来源、证据、可信度和使用反馈。

在 `/tools` 关闭 `memory` 后，自动召回停止，Agent 也不能调用记忆工具；已有记录不会删除。重新开启后继续使用。

## 存储和兼容

默认存储位置：

```text
~/.pi/agent/memory.json
```

数据使用版本化快照、跨进程锁和有界审计事件。旧的第一版记忆文件会在成功读取后迁移；损坏文件不会被覆盖。

默认后端保持 Node 和 Bun 都可运行。存储层已经与 Agent 协议分离，后续可以加入 SQLite 后端而不改变工具和界面。

`/evals` 内置一个隔离案例，检查全新 Agent 是否真的调用 `memory` 保存用户偏好，而不是只在文字上答应。隐藏验收同时检查持久化结果和实际工具链路。

## 安全边界

- API Key、令牌、密码和私钥会被拒绝。
- 记忆不能保存工具授权、审批决定或安全绕过。
- 项目证据必须位于当前项目内，符号链接不能绕过边界。
- 单个证据文件最大 2 MB。
- 网页、仓库注释和其他外部文字不能直接写入用户偏好或权限规则。
- 当前用户指令、当前代码、测试和工具结果始终高于历史记忆。
