# 单代理执行闭环

单代理执行闭环负责防止代理在修改代码后漏掉验证。

## 它做什么

1. 记录成功修改过的代码文件。
2. 记录这些修改是否经过 `verify` 或 LSP 诊断。
3. 代理准备结束但修改尚未验证时，发送一条短提醒。
4. 验证失败后，提醒代理先修复，再验证一次。

## 它不做什么

- 不增加新的模型工具。
- 不扫描项目，不读取文件，不运行后台进程。
- 不处理纯文档、图片和普通文本修改。
- 不无限重试；每次任务最多提醒两次。
- `verify` 未开启时不打扰用户。

## 为什么省 token

正常完成“修改 → 验证”的任务时完全静默。只有代理漏掉验证时，才增加一条很短的内部消息和一个继续回合。相比每轮注入长规则，绝大多数请求没有额外上下文。

## 识别的修改

- `edit`、`write`、`ast_edit`
- LSP 的重命名操作
- TypeScript、JavaScript、Python 和 Go 代码文件
- `package.json`、`tsconfig.json`、`pyproject.toml`、`go.mod` 等会影响构建的配置

## 验证规则

- 当前修改之后的成功验证才算有效，修改后旧的验证会自动失效。
- `verify` 失败时不能直接结束，应先修复并重新验证。
- 验证工具缺失或超时时停止催促，避免可选工具拖垮任务。
- 同一个“修改 + 验证状态”只提醒一次；状态变化后才可能再次提醒。
