# 可评测、可记忆、可进化的单代理架构

状态：已确认，分阶段实施

日期：2026-08-09

## 目标

把 Pi 从“能调用很多工具的代理”升级为“能稳定完成任务、知道自己哪里做得不好、经过验证后持续改进，并且始终受用户控制的单代理平台”。

## 总体结构

```text
用户 / TUI / RPC
        │
        ▼
控制层：设置、权限、能力状态、解释、诊断、恢复
        │
        ▼
运行层：任务控制器、上下文、工具路由、任务台账
        │
        ├───────────────┐
        ▼               ▼
能力层              记忆层
读写/搜索/LSP       工作/用户/项目
测试/调试/网页      经历/方法
        │               │
        └───────┬───────┘
                ▼
证据与评测层：运行记录、任务集、评分器、基线、对比报告
                │
                ▼
进化层：失败归因、改进候选、隔离评测、灰度、推广、回滚

安全层横跨所有层：能力范围、审批、沙箱、秘密、审计、内容来源
```

## 信任边界与攻击者模型

必须先承认一个事实：Pi 当前的内置工具、扩展和语言服务器都以当前用户权限运行。同一个 Node.js 进程中的扩展可以直接调用文件和网络 API，因此 `CapabilityManifest` 只能用于声明、界面提示和调用前判断，不能约束恶意扩展。真正的强制边界必须位于进程外，例如受控子进程、容器、虚拟机或操作系统沙箱。

### 需要保护的资产

- 工作区以外的个人文件、SSH/Git/云凭据和 `auth.json`。
- 源码、私有提示词、记忆、运行轨迹和评测样本。
- 权限策略、审批记录、评分器、隐藏测试和稳定版本指针。
- 用户终端、网络身份、进程资源和磁盘空间。

### 默认不可信的输入

- 网页、搜索结果、仓库代码、注释、文档、依赖包和构建输出。
- 模型输出、工具输出、自动生成的记忆和改进候选。
- 未经审核的项目扩展、Skill、LSP/DAP 服务和 MCP 服务。
- RPC 调用方，除非它已经通过本地身份与会话授权。

### 控制面与数据面

权限策略、审批、评测器和版本推广属于控制面；工具执行、候选代码和外部内容属于数据面。数据面不能写控制面文件，不能伪造批准，也不能修改用来评价自己的评分器。RPC、TUI 和无人值守模式必须调用同一个策略引擎，并记录批准者、会话、请求摘要和时间。

多会话同时运行时，设置、记忆和候选使用版本号与原子比较后写入；发现版本已变化就提示冲突，不能由最后写入者静默覆盖。

## 审查后关闭的主要漏洞

| 漏洞 | 修正后的设计 |
| --- | --- |
| 能力声明被误认为沙箱 | 明确区分“提示级”和“已强制”；恶意代码只能由进程外边界约束 |
| 候选针对公开测试刷分 | 开发集与隐藏保留集分离，评分器和保留集不可写 |
| 评测后替换候选 | 评测、批准和启用绑定同一内容摘要 |
| 自动记忆被网页或注释污染 | 不可信内容只能成为候选证据，不能直接改变规则、权限或 Skill |
| 记忆跨分支和 worktree 误用 | 绑定仓库身份、分支/worktree、版本和文件指纹 |
| 删除记忆后仍有派生副本 | 保存派生关系并执行级联遗忘 |
| Shell 授权范围过大 | 静态能力加每次调用的动态路径、命令、网络和凭据判断 |
| 凭据通过环境变量或重定向泄漏 | 环境变量白名单、来源绑定凭据、跨来源重定向移除认证 |
| 路径和网络检查后被替换 | 执行前复核路径、链接和 DNS，每次重定向重新授权 |
| 多会话与迁移导致状态覆盖 | 版本比较、原子替换、旧版本保留和损坏隔离 |
| 子进程或输出拖垮任务 | 限制进程树、时间、内存、磁盘、输出并提供熔断 |
| TUI 被长文本或控制字符破坏 | 清理 ANSI/OSC，并对窄终端、宽字符和长路径做测试 |

## 六个闭环

### 1. 任务执行闭环

```text
理解目标 → 选择工具 → 执行动作 → 自动诊断 → 验证结果 → 给出证据
```

完成任务不能只看模型是否说“已完成”。必须有一种可检查的证据，例如测试结果、类型诊断、文件差异、运行输出或用户确认。

### 2. 评测闭环

```text
固定任务 → 隔离运行 → 收集结果 → 确定性评分 → 重复多次 → 与基线比较
```

评测分四层：

1. **工具微测**：工具是否返回正确结果，耗时和输出大小是否合理。
2. **任务场景**：在小型真实仓库中完成定位、修改、修复、验证等任务。
3. **历史回归**：把真实失败转成永久测试，防止同类错误再次出现。
4. **外部基准**：后期接 Harbor、SWE-bench 和 Terminal-Bench，用于横向比较。

运行数据分成两个通道：

- **普通运行统计**：默认只保存计数、分类、耗时和结果，不进入模型上下文，也不足以重放任务。
- **评测轨迹**：只在显式评测或用户授权后保存脱敏输入、环境摘要、工具参数摘要和结果证据，用于复现；有独立保留期和删除操作。

评测集也要分层：开发集可以公开并用于调试；隐藏保留集只用于推广门禁。评分器、测试夹具和保留集放在候选不可写的位置。候选运行时默认禁网、使用临时工作区、固定依赖与随机种子，并在开始前记录操作系统、模型、推理等级、工具 schema、依赖、仓库夹具和候选内容摘要。基线与候选必须在相同环境中成对比较。

防止“刷分”的规则：

- 候选不能修改测试、评分器、基线或评测报告。
- 识别到评测环境、硬编码答案或跳过真实任务都视为失败。
- 不稳定案例进入隔离区，修复前不参与推广结论。
- 报告使用分布、置信区间和长尾值，不能只比较平均数。
- 推广采用同任务成对比较和“不明显变差”门禁，不能把随机波动当作提升。
- 10 个案例只验证评测器能工作，不能证明代理整体变好。
- 真实失败转成回归案例前要最小化内容、清除秘密并确认许可证或用户授权，不能把私有仓库片段直接打包发布。

评分优先级：

```text
安全违规为 0
    ↓
任务是否完成
    ↓
是否产生错误副作用
    ↓
Token、耗时、工具次数、重试次数
```

测试、类型检查、结构化结果等确定性评分优先；模型裁判只处理难以机械判断的部分，并且不能单独决定推广。

### 3. 记忆闭环

记忆不是聊天记录仓库，而是经过筛选、带证据、能失效的知识。

| 记忆类型 | 内容 | 是否自动进入上下文 |
| --- | --- | --- |
| 工作记忆 | 当前目标、计划、已验证事实、待办 | 是，但严格限长 |
| 用户记忆 | 用户偏好、常用工作方式 | 少量进入；敏感内容默认不记 |
| 项目记忆 | 架构、命令、约定、关键位置 | 按任务召回 |
| 经历记忆 | 某次成功或失败的过程 | 不直接注入，用于归因和评测 |
| 方法记忆 | 已验证的策略、提示词或 Skill | 匹配任务时加载 |

每条长期记忆至少包含：

```text
id
类型与作用域
内容
证据来源及其可信等级
原始证据摘要与派生记录
可信度
创建和最后验证时间
失效时间
仓库身份、分支/工作区、版本和文件指纹
记录版本与内容摘要
状态：候选 / 生效 / 过期 / 拒绝
敏感等级
```

核心规则：

- 当前文件、测试结果和用户指令覆盖旧记忆。
- 项目文件变化后，相关记忆自动标记为“待复核”，而不是继续当事实使用。
- 默认只常驻极小的用户偏好和项目摘要；其他记忆按需取回 3～5 条。
- 用户可以查看、编辑、忘记、禁用和导出记忆。
- 自动总结只能产生“候选记忆”，不能静默成为长期规则。
- 不可信网页或仓库内容只能作为带来源的证据，不能直接写入用户偏好、权限、项目规则或 Skill。
- “忘记”需要删除或失效所有派生摘要、索引和候选；备份中无法立即清除的副本必须说明保留期限。
- 记忆有数量、磁盘和 Token 配额，过期记录优先清理，不能无限增长。
- 多会话更新使用记录版本检查；冲突时保留两个候选供用户选择，不静默覆盖。
- “当前证据优先”只适用于同一事实范围；仓库文本仍然无权覆盖用户偏好、权限和安全策略。

### 4. 自进化闭环

```text
运行失败或低效
    ↓
归因：工具 / 策略 / 提示词 / 知识 / 环境
    ↓
生成一个最小候选改进
    ↓
冻结候选并生成内容摘要
    ↓
独立工作区中与当前基线做 A/B 评测
    ↓
成功率、安全、Token、速度全部过门禁
    ↓
用户查看差异、评测和候选摘要并批准
    ↓
小范围灰度
    ↓
推广或自动回滚
```

自进化分级：

| 等级 | 能力 | 默认策略 |
| --- | --- | --- |
| L0 | 只记录运行和失败 | 开启 |
| L1 | 提出记忆或经验候选 | 可开启 |
| L2 | 生成提示词、策略或 Skill 候选 | 需用户允许 |
| L3 | 自动在隔离环境中评测候选 | 需评测预算 |
| L4 | 用户批准后灰度启用 | 必须可回滚 |
| L5 | 修改核心代理代码 | 暂不进入产品路线 |

推广门禁建议：

- 安全违规必须为 0。
- 固定回归集成功率不得下降。
- 三次重复运行只适合冒烟；正式推广的样本量由任务波动和影响等级决定。
- Token 和 P95 延迟使用按任务类别设置的预算；默认警戒线可从 5% 和 10% 开始，但不是永远固定的真理。
- 除平均值外必须检查失败长尾、最大工具次数和最坏重试链。
- 新候选必须说明改了什么、为什么有效、可能影响什么。
- 评测、批准和启用绑定同一个不可变内容摘要；摘要不一致必须重新评测和批准。
- 灰度先使用影子任务或可恢复的低风险任务，不能让候选执行真实外部发布、删除或付费操作。
- 只有重复出现或高影响的失败才进入候选生成；设置频率、Token 和并发预算，避免每个任务都触发一次昂贵学习。
- 候选不能新增依赖、安装脚本、工具能力或权限范围；这类变化必须作为独立代码变更重新走人工安全审查。

### 5. 安全闭环

每个工具必须声明静态能力；每次调用还要根据实际参数生成一次动态能力请求，而不是只根据工具名字授权：

```text
读取文件 / 修改文件 / 执行进程 / 访问网络 / 使用凭据 / 使用浏览器会话
允许的路径范围
允许的命令范围
允许的域名范围
允许传给子进程的环境变量
风险等级与审批规则
```

例如 `bash` 同时可能读取文件、写文件、联网和读取环境变量，不能永久授权一个笼统的 `exec` 后认为所有命令都安全。无法可靠解析的 shell 语法、管道、重定向或嵌套解释器必须进入更严格的审批或隔离环境。

安全流程：

```text
工具请求
  → 能力策略判断
  → 内容来源与风险判断
  → 必要时询问用户
  → 沙箱或受限环境执行
  → 输出脱敏
  → 写入审计记录
```

必须遵守：

- 网页、仓库文本和工具输出属于不可信内容，不能自行授予权限。
- 不把全部环境变量交给工具或子进程；凭据按供应商和动作临时提供。
- 凭据必须绑定目标供应商和规范化后的 HTTPS 来源；重定向到其他来源时不得继续携带认证头。
- 无人值守模式默认失败关闭，高风险动作没有明确规则就不执行。
- 沙箱是可选执行后端，但安全策略和审计必须始终存在。
- 所有自动进化候选都在独立工作区和隔离凭据下运行。
- 安全测试包含提示注入、命令注入、路径越界、SSRF、密钥泄漏和权限绕过。
- 文件路径在策略判断和实际打开前都要规范化并复核，覆盖符号链接、Windows junction、UNC、设备路径和大小写差异。
- 网络策略检查每次 DNS 解析和每次重定向，默认阻止本机、局域网、云元数据地址和非 HTTP(S) 协议。
- 子进程使用环境变量白名单，并限制时间、输出、CPU、内存、磁盘、进程数量和整个进程树。
- 外部输出在进入 TUI、日志和模型前移除危险 ANSI/OSC 控制序列并统一脱敏。
- 扩展和 Skill 的安装、更新记录来源、版本和内容摘要；原生依赖或安装脚本需要单独批准。
- 权限、评分器和审计数据保存在工作区外的受保护目录，并使用原子写入；普通工具不能通过工作区修改它们。
- 审计日志有轮转和完整性校验。审计写入失败时，普通低风险任务可降级继续，高风险动作必须拒绝。

### 6. 用户操作闭环

用户不应该记住所有命令。建议提供统一入口：

| 入口 | 用途 |
| --- | --- |
| `/home` | 当前模型、工具、权限、记忆、后台任务和异常总览 |
| `/tools` | 开关工具，并说明依赖、风险和为何不可用 |
| `/settings` | 查看有效值、配置来源和修改后的影响 |
| `/memory` | 查看、搜索、添加、编辑、忘记和诊断记忆 |
| `/evals` | 运行评测、比较版本、查看失败案例 |
| `/learn` | 查看系统提出的改进候选，批准或拒绝 |
| `/safety` | 查看安全模式、权限范围和审计记录 |
| `/doctor` | 一键检查依赖、环境、服务和修复建议 |

界面默认使用短中文，只展示当前需要的操作；高级信息通过展开查看。耗时操作必须给出阶段、预计等待和降级方案。还要提供全局安全暂停入口，在不删除配置的情况下立即停止学习、后台进程、网络和高风险工具。

所有界面必须在窄终端、宽字符和长路径下截断或换行，不能让状态说明再次造成 TUI 崩溃。权限确认显示实际路径、目标域名、命令摘要和批准范围，不能只显示工具名。

## 核心数据对象

### RunRecord

记录 schema 版本、运行 ID、任务类型、工具序列、耗时、Token、重试、结果证据和失败分类。默认不保存密钥、完整代码或完整提示词；它不能单独承担可复现评测。

### EvalTrace

在显式评测中记录可复现所需的脱敏输入、环境摘要、工具调用摘要和证据引用。它与普通运行统计分开授权、存储、限额和删除，不自动进入模型上下文。

### EvalCase / EvalReport

EvalCase 定义输入仓库、目标、限制和评分器；EvalReport 记录环境摘要、候选内容摘要、基线、样本数、多次运行分布和是否通过门禁。报告由评测器签发，候选只能读取最终允许公开的部分。

### MemoryRecord

记录内容、作用域、证据、派生关系、时效、版本、状态和敏感等级；可被撤销、级联忘记和重新验证。

### ImprovementCandidate

记录候选类型、不可变内容摘要、变更内容、产生原因、影响范围、评测报告、批准者与会话、灰度状态和回滚目标。

### CapabilityManifest

记录工具可能需要的文件、进程、网络和秘密能力；每次调用再生成实际能力请求，统一供 TUI、RPC、策略引擎和审计使用。

## 故障与降级

| 故障 | 处理方式 |
| --- | --- |
| 语义搜索或记忆服务不可用 | 快速回退到 grep、文件读取和项目规则，不重复尝试 |
| 评测环境启动失败 | 候选保持未验证，绝不推广 |
| 模型裁判不可用 | 只保留确定性评分，无法判断的案例标记人工复核 |
| 记忆与当前代码冲突 | 当前代码胜出，记忆标记过期 |
| 安全策略无法判断 | 交互模式询问用户；无人模式拒绝 |
| 灰度后效果变差 | 自动停用候选并恢复上一个稳定版本 |
| 运行记录写入失败 | 不阻断普通任务，但禁止依赖该记录进行学习或推广 |
| 评分器或测试被修改 | 本轮评测作废，候选进入隔离状态 |
| 多会话同时修改状态 | 原子比较失败并提示冲突，不静默覆盖 |
| 审计写入失败 | 低风险任务提示降级；高风险动作拒绝 |
| 候选摘要与批准记录不一致 | 禁止启用并要求重新评测 |
| 数据格式迁移中断 | 保留旧文件，只切换已完整校验的新版本 |

## 隐私、性能与可靠性边界

- 默认本地存储；外发评测、记忆和遥测必须显式开启。
- 运行记录优先保存统计和哈希，不保存源码正文。
- 记忆检索有固定 Token 预算，不能因“可能有用”无限扩展上下文。
- 每种可选加速器都有超时和熔断，主任务不等待不可用的附加服务。
- 正常任务关闭评测和学习时，不增加模型调用和提示词 Token；本地事件记录只允许可测量的常数级开销。
- 存储使用原子写入、版本迁移、大小配额和损坏隔离；删除策略覆盖原记录、索引、派生物与备份期限。
- Windows、macOS、Linux 以及 TUI、JSON、RPC 模式共享相同策略语义，并分别运行路径与进程回归测试。
- 普通任务不自动运行评测或生成改进候选；完整评测在用户触发、后台空闲或 CI 中执行，并有费用上限。
- 默认记忆注入设置硬 Token 上限；无关记忆为 0 条，可选语义检索超时后立即回退。
- 热路径不做同步磁盘写入；用基准验证开启普通统计后的 P95 总耗时增幅不超过 1%。

## 仍然存在且必须向用户说明的风险

- 宿主机模式下，同进程扩展仍拥有当前用户权限；只有隔离后端提供强制边界。
- 提示注入无法被完全识别，只能通过来源隔离、最小权限和人工批准降低影响。
- 开放式任务不一定有完美评分器，部分推广仍需要人工复核。
- 回滚只能恢复 Pi 的本地配置、记忆和候选，不能撤销已经发生的外部副作用。
- 请求发送给模型供应商后受该供应商的数据政策约束；本地删除不能撤回已经发送的数据。
