# Todo 任务计划

`todo` 用来让主代理在长任务里记住进度。它不执行命令、不搜索代码，也不会自动增加模型轮次。

## 什么时候使用

适合：修改多个文件、包含多个验证步骤、可能跨上下文或重启继续的任务。

不适合：简单问答、读取一个文件、只改一处文字等单步任务。

## 用户怎么用

1. 打开 `/tools`，用右方向键开启 `todo`。选择会永久保存，不需要每次重开。
2. 正常描述一个多步骤任务，主代理会建立并更新计划。
3. 输入 `/tasks` 查看完整计划、稳定任务 ID、阻塞原因和完成证据。

编辑器下方只显示一行紧凑进度，例如：

```text
任务 2/5 · 当前 t3 运行相关测试 · 阻塞 1
```

## 状态含义

| 标记 | 状态 | 含义 |
|---|---|---|
| `→` | `in_progress` | 当前正在处理 |
| `○` | `pending` | 等待处理 |
| `✓` | `completed` | 已完成，并带验证证据 |
| `!` | `blocked` | 有明确阻塞原因 |
| `-` | `abandoned` | 已明确放弃 |

同一时间只有一个当前任务。当前任务完成、阻塞、放弃或删除后，会自动选择下一项待办。

## 一致性保护

- 阶段和任务使用不会重复的 `pN`、`tN` ID，不依赖标题匹配。
- 每次修改必须使用最新 `revision`，旧上下文不能覆盖新进度。
- 完成任务必须写入简短证据，例如“相关 Vitest 11 项通过”或“npm run check 通过”。
- 状态保存在当前会话分支中；恢复会话或切换分支时自动恢复对应计划。
- 完整快照不会发给模型。每轮只注入当前任务和有限数量的未完成项，最多 2400 个字符。

## 工具操作

模型可使用 `view`、`set_plan`、`add`、`start`、`complete`、`block`、`unblock`、`abandon`、`reopen`、`remove` 和 `clear`。除 `view` 外都需要上一次结果中的 `expected_revision`。

遇到 revision 冲突时，先执行一次 `view` 获取最新状态，再重试一次；不要循环重试。
