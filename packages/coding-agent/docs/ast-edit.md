# 结构化修改与 Diff 预览

Pi 有三种写文件工具：

| 工具 | 适合什么情况 |
|---|---|
| `edit` | 已知文件和具体位置，精确修改一处或几处 |
| `write` | 新建文件，或者完整重写一个文件 |
| `ast_edit` | 同一种代码写法分布在多个位置，需要按代码结构批量修改 |

## `ast_edit` 为什么更准确

普通文字替换看不懂代码。它可能把注释、字符串里的相同文字也改掉。

例如要把真实调用：

```ts
console.log(value);
```

改成：

```ts
logger.info(value);
```

可以使用：

```json
{
  "pattern": "console.log($$$ARGS)",
  "replacement": "logger.info($$$ARGS)",
  "language": "typescript",
  "path": "src"
}
```

`$$$ARGS` 表示“这里原本的全部参数”。因此参数会原样保留，注释和字符串不会被当成调用。

## 写入流程

```text
扫描代码结构
  -> 在内存中生成全部新内容
  -> 展示多文件 Diff
  -> 按当前安全模式确认
  -> 再次检查文件是否变化
  -> 全部原子写入
```

任何文件验证失败，整批修改都会停止。写入中途失败时，已经写入的文件会自动回滚。

## Diff 怎么看

- `+绿色`：新增内容。
- `-红色`：删除内容。
- 标题显示文件状态，以及新增、删除的总行数。
- 大 Diff 默认折叠中间部分。展开工具输出可查看全部内容。
- `edit`、`write` 和 `ast_edit` 使用相同样式。

`write` 覆盖旧文件时会读取旧内容，所以现在能看到完整的新旧差异；新文件会显示“新建”。

## 安全上限

- 默认最多修改 100 处，可用 `max_matches` 调整，最高 1000。
- 单次最多修改 100 个文件。
- 搜索范围最多 5000 个代码文件。
- 准备变更超过 20 秒会停止。
- 只能修改当前项目中的文件。

超限时应缩小 `path`。不要用相同参数反复重试。
