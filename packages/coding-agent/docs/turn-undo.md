# 撤销最近一次代理文件修改

Pi 会在每次代理开始工作前记录 Git 工作区基线。代理完成后，如果项目文件发生变化，界面会提示：

```text
已保存本回合 4 个文件的修改，需要时输入 /undo-turn。
```

输入：

```text
/undo-turn
```

Pi 会先展示文件清单，再要求确认。取消或按 `Esc` 不会修改文件。

## 能撤销什么

一次撤销处理最近一个代理回合的全部净文件变化：

- 修改的文件恢复原内容；
- 新建的文件被移除；
- 删除的文件被重新创建；
- 重命名按“恢复旧文件、移除新文件”处理；
- `edit`、`write`、`lsp rename`、`ast_edit` 和模型调用终端产生的 Git 可见变化使用同一快照。

恢复的是代理开始前的真实工作区。项目原来已有的暂存、未暂存和未跟踪内容不会被重置到 `HEAD`。

## 安全规则

撤销前会再次读取全部目标文件。如果任何文件在代理结束后又被用户、编辑器或其他程序修改，整次撤销会停止，不覆盖任何文件。

多文件恢复先完成全部校验和临时文件准备，再替换目标。执行中失败时会反向恢复已经处理的文件。

以下操作不会发生：

- 不运行 `git reset --hard`；
- 不修改 Git 索引、提交、分支或 stash 列表；
- 不处理项目外路径；
- 不在无交互模式中自动撤销；
- 不恢复命令产生的网络、数据库、进程或其他外部副作用。

代理运行期间如果用户同时手动修改文件，这些变化无法和代理变化可靠区分，确认界面会明确说明它们也会一起撤销。建议代理工作时不要同时编辑同一项目。

## 范围和限制

- 当前完整模式只支持已有提交的 Git 项目。
- 项目必须已经通过 Pi 的项目信任检查。
- Git 忽略文件和子模块不进入快照。
- 单文件上限为 5 MiB，单快照上限为 50 MiB。
- 回合开始时最多记录 500 个未跟踪文件。
- 单回合最多处理 500 个候选变化文件。
- 每个工作区保留最近 20 个快照。
- 同一项目同时只允许一个 Pi 会话记录快照；其他会话会收到提示并安全跳过。
- 如果代理改变了 Git `HEAD`，本回合不会创建撤销快照，避免暗中改写提交历史。

快照保存在 Pi 用户配置目录的 `turn-undo` 子目录，不写入项目，也不会发送给模型。
