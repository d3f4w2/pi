# ADR 0018：以评测门禁约束代理自进化

- 状态：Accepted
- 日期：2026-08-09
- 影响范围：coding-agent 的评测、记忆、Skill、策略、权限和用户界面

## 背景

Pi 已具备较完整的单代理执行能力，但缺少稳定的方法判断一次提示词、策略、Skill 或工具改动是否真的提高了任务完成率。直接根据单次成功、模型自评或用户主观感受推广改动，容易产生过拟合、Token 膨胀、安全回归和无法解释的行为变化。

自改进代理研究证明“生成候选并通过经验结果选择”有潜力，但生产工具必须额外解决隔离、权限、可复现、人工控制和回滚问题。公开固定任务还会产生过拟合和刷分风险；如果候选能够修改评分器、测试或批准后的内容，一套看似完整的门禁也会失效。

## 决策

采用“候选改进 + 隔离评测 + 人工批准 + 灰度 + 回滚”的自进化模型。

1. 任何自动学习结果首先是候选，不直接改变稳定行为。
2. 第一阶段只允许候选修改项目提示词和触发式策略；事实记忆由独立的证据记忆闭环管理，Skill 代码生成继续禁用。
3. 候选在独立工作区、受限权限和冻结基线上运行。
4. 候选、评测、批准和启用绑定同一个不可变内容摘要。
5. 开发集与隐藏保留集分离，评分器和保留集位于候选不可写区域。
6. 评测同时比较成功率、安全、Token、延迟、工具调用、重试和长尾失败。
7. 普通运行统计与可复现评测轨迹分开存储，后者必须显式授权并脱敏。
8. 确定性测试和规则优先于模型裁判。
9. 候选只有通过门禁并获得用户批准后才能在低风险任务中灰度启用。
10. 灰度期间继续对比稳定版本；退步时自动停用并回滚。
11. 核心代理代码的自主修改不在当前产品范围内。

## 原因

- 没有评测的“学习”只是积累未经证实的规则。
- 单次运行有随机性，需要重复运行和稳定基线。
- 可见固定评测会成为优化目标，需要隐藏保留集和不可修改的评分器。
- Token 和延迟也是产品质量，不能只追求成功率。
- 自动修改核心代码的故障半径过大，难以保证权限边界。
- 人工批准让用户保留最终控制权，也使行为变化可解释。

## 备选方案

### 方案 A：代理直接修改并启用自己

优点是反馈快。缺点是安全风险、回归风险和不可解释性最高，因此拒绝。

### 方案 B：只记录数据，永不自动提出改进

风险最低，但数据无法形成生产力，也无法实现自进化，因此只作为阶段 0 的临时状态。

### 方案 C：只靠模型裁判选择候选

实现简单，但容易偏好表面质量、受到提示影响，也无法可靠判断代码是否真正工作，因此拒绝作为唯一门禁。

### 方案 D：只使用完全公开的固定任务集

容易调试，但候选可能记住任务、识别评测环境或针对评分器取巧，因此只适合作为开发集，不作为唯一推广门禁。

## 结果

正面影响：

- 每个改进都有来源、证据和可量化收益。
- 能及时发现 Token、延迟和安全退步。
- 用户可以理解、拒绝和撤回行为变化。
- 历史失败可以转成长期回归资产。

代价：

- 需要维护评测案例、环境和基线。
- 重复评测会消耗时间和计算资源。
- 部分开放式任务仍需人工复核。
- 自进化速度会比“直接上线”慢，但稳定性更高。

## 约束

- 评测失败或记录不完整时，候选保持未验证状态。
- 评测环境不能读取生产凭据。
- 候选不能写入评分器、隐藏保留集、基线、权限策略、审批记录或评测报告。
- 评测、批准和启用的候选内容摘要必须完全一致。
- 三次重复只作为冒烟检查；正式推广样本量依据波动和风险确定。
- 运行记录默认不保存完整源码、提示词或秘密。
- 可复现轨迹需要单独授权、脱敏、保留期和级联删除。
- 安全违规不能用成功率提升抵消。
- 灰度阶段禁止不可逆外部动作、付费操作和生产凭据。
- 候选不得自行新增依赖、安装脚本、工具能力或权限范围。
- 用户可以完全关闭记录、学习和候选生成。

## 后续验证

先实现 10 个离线确定性冒烟任务，仅验证以下基础设施能力：

1. 当前稳定版本可以保存为基线。
2. 同一候选可以重复运行并展示波动。
3. 明显降低成功率或提高 Token 的候选会被拒绝。
4. 试图访问越界路径、网络或凭据的候选会被拒绝。
5. 修改评分器、替换已批准候选或伪造报告会被拒绝。
6. 批准后的候选可以在低风险影子任务中灰度启用并一键回滚。

冒烟通过不代表候选可以进入产品。正式推广前还要建立开发集与隐藏保留集、测量案例波动，并验证统计门禁。

## 第一阶段实现决议

- 普通运行只聚合脱敏指标，同类信号重复出现后才询问用户。
- 候选类型先限制为项目级短提示和触发式策略；Skill 代码生成与核心源码自修改继续禁用。
- 候选生成采用一次性授权和二次内容确认，生成期间禁用其他工具。
- A/B 复用现有隔离 Agent 评测器，基线与候选使用相同模型、思考等级、工具、夹具、隐藏验收和预算。
- 确定性验收负责阻断不能工作的候选；Token、延迟和工具链差异作为证据展示，由用户判断收益。
- 灰度只在候选实际注入的任务中计数；失败立即停用，达到观察次数后暂停候选并等待用户正式启用。
- 所有状态变化写入版本化审计日志，评测、批准和启用都校验候选 SHA-256 摘要。
- 实现与操作说明见 `docs/self-evolution.md`。
