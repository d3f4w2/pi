# ADR 0028：隔离运行真实 Agent 能力评测

## 状态

Accepted

## 背景

现有 `/evals` 只运行固定代码和评测器自检，没有调用模型，因此不能衡量 Agent 的理解、搜索、修改和验证能力。代码回归测试、评测器自检和 Agent 能力评测必须分开。

## 决策

- `/tests` 运行已批准的代码回归案例，不调用模型。
- `/evals` 在临时项目中启动全新 Pi-go RPC 子进程，执行真实任务并消耗当前模型额度。
- `/evals-dev` 保留固定的评测器自检、报告和基线工具。
- 每个能力类别暂时只内置一个案例：代码定位、Bug 修复、修改后验证、失败恢复、范围与 token 控制。
- Agent 只能看到公开项目和任务，隐藏验收文件在 Agent 结束后才写入。
- 每个案例有两分钟硬超时；运行前必须由用户确认费用和时间。
- 效率门限制输出 token 和工具调用次数；输入 token 与总 token 只记录，因为系统提示和工具 schema 是不可避免的启动成本。
- 运行期间在输入框上方持续显示准备、启动、工作、工具调用、隐藏验收和清理阶段。
- 结果记录模型、思考等级、通过状态、耗时、token 和工具调用，不保存密钥或完整对话。

## 备选方案

- 在当前会话内模拟：无法隔离上下文，也不能代表全新 Agent，拒绝。
- 只运行固定函数：便宜但不测 Agent 能力，移动到 `/evals-dev`。
- Agent 直接读取验收测试：容易针对答案修改，评测不公平，拒绝。

## 后果

真实评测会产生模型费用并需要更长时间，但结果代表 Agent 实际完成任务的能力。子进程崩溃或超时不会拖垮当前交互会话。
