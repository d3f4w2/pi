# ADR 0029：可展开的 Agent 评测执行链路

## 状态

Accepted

## 问题

只显示“通过或失败”无法解释 Agent 是如何完成任务的，也无法定位启动慢、工具慢、无效调用或 token 浪费。直接保存完整 RPC 日志又会产生大量噪声，可能包含文件正文、命令输出或敏感参数。

## 决策

- 每次真实 Agent 评测保存结构化执行链路，而不是完整原始日志。
- 链路记录准备、启动、Agent 工作、工具调用、隐藏验收和清理阶段的相对开始时间、持续时间与状态。
- 工具调用只保留路径、查询、模式、操作等有分析价值的输入字段；写入正文只记录字节数。
- 工具结果和 Agent 最终回答只保留脱敏、压缩后的短摘要。单条摘要最多 180 个字符，单个案例最多 40 条链路记录。
- 单独记录准备、启动、Agent、验收、清理和总耗时，并拆分输入、输出、缓存 token、工具次数和错误次数。
- 报告使用自定义会话条目保存，不进入模型上下文，因此展开报告不会增加后续对话 token。
- 默认只显示结论摘要；沿用全局 `Ctrl+O` 展开机制查看完整链路，不增加新的快捷键。
- 每次运行自动查找同一案例的上一次结果，展示状态、配置、耗时、token、错误次数和工具构成的前后数值与差值。工具构成使用明确的“上次”和“本次”两行，本次仅标注发生变化的工具计数；完整顺序只在执行链路中展示一次。
- 自动对比不设基线、不评分，也不标记提升或退步；好坏由用户结合任务和链路判断。
- 旧结果继续可读；没有链路数据时明确标记为旧报告。

## 备选方案

- 只增加更多最终统计：仍然看不到顺序和中间结果，拒绝。
- 保存完整 RPC 事件和工具输出：信息最全，但噪声、存储和敏感数据风险过高，拒绝。
- 每次完成后打开阻塞式弹窗：会打断连续运行多个案例，也不便于稍后回看，拒绝。
- 增加 `baseline`、`compare` 或 `history` 命令：增加记忆成本，而且用户期望每次运行后立即看到变化，拒绝。

## 后果

用户可以从一个结果追溯到具体执行步骤，并区分模型工作慢、工具慢和验收慢。报告保持有界且不会进入模型上下文；代价是摘要不等于完整调试日志，必要时仍需单独复现失败任务。
