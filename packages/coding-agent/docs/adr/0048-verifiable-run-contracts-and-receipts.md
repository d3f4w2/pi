# ADR-0048: 可验证执行契约与完整性回执

## Status

Accepted

## Context

交互式 Agent 擅长探索和修改，但“模型回复已完成”不等于工程结果已经通过检查。现有 `verify`、任务台账和运行指标各自提供了验证、证据和低基数统计，却没有一个适合本地脚本与 CI 的单次执行边界。

新的执行入口必须同时满足：复用现有 Agent 能力；在脏工作区中识别本次运行产生的改动；不保存提示词、源码或工具原始输出；由 Agent 之外的进程独立复跑确定性检查；产出可供后续 Agent Eval/CI 消费的稳定数据。

## Decision

- 新增 `pigo run`，它是现有单 Agent 的受控外壳，不建立第二套工作流或工具执行器。
- 运行开始前将任务、允许范围、验证项和预算解析成版本化契约；执行期间不再读取可能被 Agent 修改的契约文件。
- 第一版要求 Git 工作区。通过 Git 索引、前后脏文件指纹和 HEAD 变化检测本次运行的净改动，避免对整个仓库做两次全量内容哈希。
- 范围在执行结束后进行合规检测。越界修改或 HEAD 变化使结果成为 `noncompliant`；该机制不宣称是强沙箱。
- Agent 以现有 JSON 事件流子进程运行。父进程只聚合工具计数、错误、Token、费用和最终回复摘要，不保存原始事件、工具参数、源码或回复正文。
- Agent 结束后，父进程直接调用 `VerifyService`。验证结果来自独立执行，不信任模型对测试状态的描述。
- 每次运行写入版本化 JSON 回执。回执主体使用稳定键序列化并计算 SHA-256；显式目标文件已存在时拒绝覆盖。
- 回执 schema 作为后续 Agent Eval/CI 的输入边界。评测层只能消费证据，不反向影响当前运行判定。

## Consequences

### Positive

- 人和 CI 可以区分 `verified`、`completed`、`unverified`、`failed` 与 `noncompliant`。
- 现有模型、工具、会话策略、缓存和审批保持单一实现。
- 默认回执写在项目外，不污染被执行仓库；不保存高敏感内容。
- Git 增量快照的成本与工作区改动数量相关，而不是与仓库总大小线性相关。

### Negative

- 第一版只支持 Git 工作区；非 Git 目录需要先初始化仓库。
- 范围检查是事后发现，不能阻止恶意进程在运行时越界写入。
- 外层强制超时或预算停止可能在工具写入中途终止进程，仍需依靠现有原子写入与工作区证据暴露状态。

### Neutral

- 回执完整性摘要能发现文件内容变化，但不是签名；任何能改写文件的人也能重新计算摘要。签名和远端证明属于后续 CI 信任层。

## Alternatives Considered

**只记录 `pigo -p` 的日志**

拒绝。日志不能证明改动范围、独立验证结果或证据完整性，也容易保存敏感内容。

**建立独立多步骤工作流引擎**

拒绝。它会复制 AgentSession、工具权限和缓存路径，使交互模式与 CI 模式行为漂移。

**执行前后全仓文件哈希**

拒绝。大仓库冷启动成本过高。Git 索引已经提供干净文件的内容身份，只需哈希运行前后脏文件。

**把范围检查描述为沙箱**

拒绝。事后证据和执行时隔离是不同安全边界；强隔离继续由现有容器与 OS sandbox 提供。
