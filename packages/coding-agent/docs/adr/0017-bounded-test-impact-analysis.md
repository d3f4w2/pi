# ADR-0017: 使用有界临时依赖图选择受影响测试

## Status

Accepted

## Context

`verify auto` 原来主要根据被修改文件的名称寻找测试。例如修改 `shared/parser.ts` 时，`user-api.test.ts` 虽然通过 `user-service.ts` 间接依赖它，但名称不相同，因此可能漏测。

默认运行整个测试套件不能作为补救方案。大型仓库可能包含端到端测试、真实 API、凭据依赖或长时间任务。目标是在不增加模型 Token 的前提下，提高相关测试召回率，同时保持时间和资源开销可预测。

## Decision

在 `verify auto` 内建立包级、临时、只读的反向导入图：

1. TypeScript/JavaScript 使用 TypeScript 模块解析器处理导入和路径别名。
2. Python 解析常见绝对导入、相对导入和 `src/` 布局。
3. 从目标文件开始反向广度优先遍历，按依赖距离排序测试。
4. 合并原有文件名匹配结果作为保守补充。
5. 限制为 5000 个文件、512 KiB/文件和 20 个测试。
6. 超限或分析不完整时提示用户并退回文件名匹配；不运行全量测试。
7. 依赖图不持久化，不发送给模型，不启动语言服务器。

Go 暂时继续使用包级 `go test`，因为包是 Go 可靠的最小编译和测试单位。

## Consequences

### Positive

- 能找到文件名完全不同的间接依赖测试。
- 通过 `tsconfig` 路径别名的项目仍可准确解析。
- 只消耗本地 CPU、内存和少量文件读取，不消耗模型 Token。
- 严格上限让大型仓库中的耗时可预测。
- 失败时保持原有能力，不会把可选优化变成任务阻塞点。

### Negative

- 动态导入、反射和运行时插件关系仍可能漏掉。
- 首次分析需要读取当前包的源码，超大包会比单纯文件名匹配慢。
- Python 静态导入解析不等同于完整解释器语义。

### Neutral

- 依赖图每次按需重建，不存在陈旧索引，但也不复用上次结果。
- 跨包影响默认不传播；完整 monorepo 验证仍需用户明确触发。

## Alternatives Considered

**始终运行完整测试套件**

- 拒绝：耗时和副作用不可预测，可能启动端到端测试或真实 API。

**只保留文件名匹配**

- 拒绝：速度快，但无法解决间接依赖导致的漏测。

**依赖正在运行的 LSP 查找引用**

- 拒绝：语言服务器可能未安装、未启动或正在初始化，不能成为验证闭环的硬依赖。

**持久化完整代码知识图谱**

- 拒绝：索引维护、失效处理和存储成本明显高于当前需求；临时导入图已经能解决主要问题。
