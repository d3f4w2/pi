# ADR 0027：分开回归测试与评测器工具

## 状态

Superseded by ADR 0028。本文记录过渡设计；最终命令边界以 ADR 0028 为准。

## 问题

`/evals` 主菜单同时展示回归案例、评测报告、基线比较和基础设施自检。普通用户只想确认“修好的问题有没有再次出现”，却必须先理解评测器内部概念。

例如，“查看测评报告”看起来像是在评测代理能力，实际展示的是评测器离线自检报告。两者含义不同，放在同一层会误导用户。

## 决策

`/evals` 主菜单只保留三个入口：

1. 运行最近案例。
2. 选择历史案例。
3. 开发者工具（一般不用）。

报告、基线、比较、失败项和离线自检全部移入开发者工具。开发者菜单标题明确说明：这些操作检查评测器本身，不测试代理能力。

自动制作回归案例仍由真实任务中的“失败、修改、验证通过”触发，不在 `/evals` 菜单中增加手动制题入口。

## 兼容性

现有 `/evals test`、`run`、`latest`、`baseline`、`compare` 和 `failures` 命令保持不变。此次只调整交互菜单和文案，不改变执行器、存储格式或报告格式。

## 结果

- 普通用户只需要理解“回归案例”。
- 开发者能力仍然可用，但不会干扰日常操作。
- 菜单切换不调用模型、不联网，也不增加 token 消耗。
