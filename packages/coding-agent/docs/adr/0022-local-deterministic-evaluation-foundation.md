# ADR 0022：先建立本地确定性评测基础

- 状态：Accepted
- 日期：2026-08-09
- 影响范围：coding-agent 的运行记录、评测、命令入口和本地存储

## 问题

Pi 已经记录工具调用和任务结果，但还不能稳定回答“这次改动是否比基线更好”。直接运行真实模型任务会引入费用、随机性、网络和凭据风险，也会让第一版评测器本身难以验证。

## 决策

第一版采用两层结构：

1. 把现有运行指标升级为脱敏的 `RunRecord`，增加 Token、费用、重试和验证证据摘要。
2. 定义独立的 `EvalCase`、`EvalReport` 和确定性评分器。
3. `/evals run` 只运行 10 个完全离线的基础设施冒烟案例，不调用模型、不联网、不读取生产凭据。
4. `/evals baseline` 保存最近报告为本地基线；`/evals compare` 比较成功率、Token、P50/P95 延迟、工具调用和重试。
5. 报告必须显示“基础设施冒烟不代表代理能力提升”，防止把自检结果误当产品结论。
6. 普通运行只做常数级内存计数和一次最佳努力写入；评测只在用户显式调用时运行。
7. 旧版运行记录在读取时迁移，损坏行跳过，不阻断 Pi 启动。

## 数据流

```text
普通任务事件
  → RunMetricsTracker
  → RunRecord（无提示词、源码、路径和工具输入）
  → 本地 JSONL

/evals run
  → 内置离线 EvalCase
  → 确定性评分器
  → EvalReport
  → 基线保存 / 对比 / 失败查看
```

## 为什么不直接跑真实代理任务

真实任务需要隔离工作区、候选不可写控制目录、固定模型环境和隐藏保留集。第一版如果同时实现这些内容，故障来自评测器还是代理本身将难以区分。离线冒烟先验证数据模型、评分、存储和比较链路；它通过后再接真实开发任务。

## 结果

- 普通任务不增加模型调用或提示词 Token。
- 用户可以立即验证评测基础是否工作，并保存可比较的本地报告。
- 后续真实任务复用同一报告和比较层。
- 第一版不能证明代理变强，也不能作为自动推广门禁。

## 验收

- 10 个离线案例可重复运行且结果稳定。
- 明显的结果、Token、耗时或工具错误退步能够被比较器发现。
- 报告和运行记录不包含路径、源码、提示词、工具输入或密钥。
- 损坏记录被跳过；存储失败不影响主任务。
- 关闭或从不调用 `/evals` 时不产生额外模型调用。
