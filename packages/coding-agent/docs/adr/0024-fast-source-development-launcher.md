# ADR 0024：开发启动直接使用 Node 原生 TypeScript

- 状态：Accepted
- 日期：2026-08-09
- 影响范围：本地 `pi-dev` 启动、TypeScript 源码执行、PowerShell 开发入口

## 问题

原来的 `pi-dev` 每次启动都调用 `tsx`。即使源码没有变化，也会重复初始化转译器并处理 TypeScript 入口。Windows 热启动实测约为 4–8 秒，慢于应用自身约 1.3 秒的启动时间。

## 决策

开发入口改用 Node 的原生 TypeScript strip-only 执行：

```text
pi-dev
  → scripts/pi-dev.ps1
  → node --experimental-strip-types
  → packages/coding-agent/src/cli.ts
```

Node 只删除可擦除的类型语法，不做完整转译。项目根规则已经要求 `packages/*/src` 使用可擦除 TypeScript，因此该路径与代码约束一致。

## 为什么不直接运行 dist

运行已构建的 `dist/cli.js` 热启动约 1.3 秒，但修改源码后必须重新构建，容易运行旧代码。原生执行源码约 1.6 秒，只慢约 0.3 秒，同时保持修改立即生效，更适合日常开发。

## 为什么不使用常驻进程

常驻进程理论上可以继续减少进程冷启动，但会引入状态污染、端口协调、僵尸进程和源码热重载一致性问题。当前主要浪费来自重复转译，删除这一层已经解决主要瓶颈。

## 边界

- 不跳过资源加载、扩展注册、凭据读取或安全检查。
- 不自动运行构建，不产生陈旧的 `dist`。
- 命令参数原样传给 CLI。
- 找不到 Node 或 CLI 入口时立即给出明确错误。
- 启动后工作目录仍是仓库根目录，退出后恢复调用者原目录。

## 验收

- `pi-dev --version` 返回当前源码版本。
- 参数可以完整透传。
- 热启动中位数应明显低于旧 `tsx` 路径。
- 退出后 PowerShell 所在目录不变。

2026-08-10 在同一份最终源码上的复测结果为：版本命令中位数从 0.194 秒降到 0.092 秒，降低 52.6%；RPC 可用时间中位数从 6.165 秒降到 2.031 秒，降低 67.1%。扩展按需加载还把 Node 原生版本命令从本轮早期的 1.946 秒降到 0.092 秒。完整环境、阶段区别、P95 和原始样本见 [性能与能力基线](../performance.md)。
