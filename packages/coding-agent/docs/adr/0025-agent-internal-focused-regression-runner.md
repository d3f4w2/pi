# ADR 0025：代理内部提供一条命令运行已批准回归测试

- 状态：Accepted
- 日期：2026-08-09
- 影响范围：`/evals`、回归测试审批记录、测试进程执行和 TUI 结果展示

## 问题

回归测试写入项目后，只提示“运行专项测试”仍然要求用户判断测试框架、工作目录和参数。测试已经由代理创建，运行入口也应该由代理提供，但执行决定仍由用户掌握。

## 决策

只增加一个用户入口：

```text
/evals
  → 测试最近案例
  → 选择历史案例
  → 查看测评报告
  → 高级功能
```

case 创建成功时只提示打开 `/evals`，不要求用户记忆子命令。选择测试后执行以下固定流程：

```text
读取批准记录
  → 定位 case
  → 校验项目边界、文件存在和批准时的内容哈希
  → 识别最小测试运行器
  → 直接启动进程，不经过 shell
  → 在 TUI 显示通过或失败
```

首版支持 `node:test`、Vitest、pytest 和 Go test。只运行 case 对应的文件或目录，不隐式扩大到全仓测试。

## 安全边界

1. 只有用户明确打开 `/evals` 并选择测试操作后才执行测试代码。
2. 只运行已经经过完整预览和二次批准的 case。
3. 文件内容与批准哈希不一致时拒绝执行，避免运行未经审查的修改。
4. 文件真实路径必须仍位于当前项目内，阻止符号链接越界。
5. 不拼接 shell 字符串；可执行程序和参数分别传递。
6. 单次运行限制为 60 秒，输出进行有界截断。
7. 测试框架不明确或混用多种语言时拒绝猜测。

## 为什么不自动运行

测试文件本身是可执行代码。写入批准不等于执行批准，因此保持一次显式的用户命令。该命令已经包含 case 和运行器选择，不再要求用户进入外部终端。

## 为什么保留内部子命令

`test`、`run`、`latest`、`baseline`、`compare` 和 `failures` 仍可供脚本和开发者直接调用，但普通用户入口不展示这些记忆负担。最常见动作“刚创建，马上测试”放在菜单第一项。

## 验收

- 新 case 结果中只提示打开 `/evals`。
- `/evals` 能选择并运行最近或历史 case。
- 支持的四类运行器只执行目标范围。
- 文件缺失、越界、哈希变化和未知框架不会启动进程。
- 超时、退出码和有限输出能在 TUI 中明确展示。
