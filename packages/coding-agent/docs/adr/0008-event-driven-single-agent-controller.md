# ADR-0008：使用事件驱动的单代理执行闭环

## 状态

Accepted

## 背景

Pi 已经具备编辑、结构搜索、LSP、验证和任务账本，但这些工具是否形成闭环仍依赖模型主动遵守提示。继续增加长系统提示会提高每次请求的 token 成本；自动在每次写入后运行完整检查又会拖慢连续编辑。

## 决策

增加一个隐藏的内置扩展，通过现有扩展事件维护轻量状态机：

- 只观察成功的代码修改和验证工具结果。
- 修改后准备结束且尚未验证时，发送一次短 `steer`。
- 正常路径静默，不注册新工具，不扫描文件系统。
- 每次代理运行最多提醒两次；验证不可用或超时时放行。

## 结果

### 正面

- 修复“改完就结束”的可靠性缺口。
- 正常任务没有新增工具 schema 和模型回合。
- 控制逻辑独立于语言，可复用现有多语言验证。
- 状态机可以用纯单元测试覆盖。

### 负面

- 漏检时会多一个模型回合和一次验证。
- 只能识别已知的写入工具与代码路径；未知工具需要显式接入。

### 中性

- 控制器不替代 `verify`、LSP 或任务账本，只协调它们的完成条件。

## 备选方案

### 每轮注入完整工作流提示

拒绝。实现简单，但所有任务都会持续消耗 token。

### 写入后立即自动运行验证

拒绝。连续编辑会重复启动检查进程，明显增加延迟。

### 新增一个“控制器工具”让模型调用

拒绝。它扩大工具 schema，且仍然依赖模型记得调用。

### 在核心 agent loop 中硬编码

拒绝。会把 coding-agent 的产品策略下沉到通用 agent 包，增加耦合。
