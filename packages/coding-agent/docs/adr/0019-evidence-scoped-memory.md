# ADR 0019：长期记忆采用证据学习闭环

- 状态：Accepted
- 日期：2026-08-10
- 影响范围：coding-agent 的 Agent 协议、上下文、存储、项目证据和用户界面

## 背景

第一版原型通过固定中英文句式识别“请记住”，保存 `key + 文本`，再用关键词重叠召回。这种实现能通过少量演示，但无法处理自然表达、语义冲突、事实时间版本和局部代码变化。它只是自动便签，不是学习闭环。

完整记忆必须回答：谁提出、谁批准、它描述哪个事实、来自什么证据、何时有效、替代了什么、是否仍可信，以及它过去是否帮助过任务。

## 决策

1. 记忆分为用户、项目、经历和方法四类。临时工作状态继续留在会话和任务账本，不进入长期记忆。
2. 自然语言理解交给已经在执行任务的主模型。移除固定句式解析器，`memory` 作为始终可用的结构化工具。
3. 用户明确要求记住时调用 `remember` 并直接生效；Agent 自己发现的经验调用 `propose`，必须经用户批准。
4. 每个 Agent 任务最多提出一条候选。任务结束后立即显示批准、拒绝和稍后处理，不要求用户记住另一个命令。
5. 没有成功的持久化或删除回执，Agent 不得声称已经记住或忘记。
6. 记忆使用 `subject + predicate + value` 表示事实身份和值。同一主体和属性的新值会建立时间替代关系，旧值保留为历史。
7. 项目、经历和方法记忆必须绑定项目文件。优先保存精确原文锚点，只有锚点改变时才失效；整文件摘要只是保守回退。
8. 项目身份按规范化仓库确定。分支是来源元数据，不是默认可见性边界；当前证据决定事实是否仍有效。
9. 新会话首轮最多注入三条核心用户偏好，并为当前任务相关项目记忆保留容量；其他历史由 Agent 按需召回。
10. 召回使用本地精确匹配、BM25 风格稀有度、中文片段、证据、可信度和历史效果联合排序；默认不调用额外模型或向量服务。
11. 每次召回和使用反馈进入有界审计事件，支持统计召回、采用、帮助和伤害。
12. 默认存储采用带锁的版本化便携后端，保证 Node 与 Bun 一致运行；Agent 协议依赖存储接口而不是具体格式。
13. API Key、权限批准、安全绕过和不可信来源的行为指令不能进入记忆。

## 原因

- 结构化 claim 比自然语言 key 更容易发现同一事实的冲突。
- 主模型已经拥有完整上下文，利用它提出候选不需要再次支付后台模型的 Token 和等待时间。
- 精确证据锚点能同时避免整文件摘要的误失效和旧代码事实的误召回。
- 首轮小型上下文加按需召回可以控制提示词、缓存和延迟。
- 时间历史和使用反馈让系统可以解释为什么召回一条记忆，并通过评测判断它是否真正有益。
- 便携后端避免 `node:sqlite` 破坏 Bun 二进制；接口边界保留后续 SQLite/FTS5 实现空间。

## 备选方案

### 固定语言规则

拒绝。规则只能覆盖提前想到的表达，还可能吞掉包含后续任务的用户输入。

### 每轮后台模型自动总结

拒绝作为默认路径。它重复读取主模型已经看过的上下文，增加 Token、延迟和错误面。主 Agent 可以在当前任务内提出最多一条候选。

### 默认向量数据库或图数据库

暂不采用。当前本地规模最多数百条，结构化 claim 和混合全文排序足以建立基线。只有专项测评证明语义或多跳召回是主要瓶颈时再增加可选通道。

### 直接使用 `node:sqlite`

暂不采用为默认后端。Node 运行时支持，但当前 Bun 二进制不能解析该模块。引入运行时专属存储会破坏发布产物的一致性。

## 后果

正面影响：

- 中文、英文和混合任务共用同一协议。
- 用户明确记忆不再需要重复进入 `/memory` 批准。
- Agent 可以学习，但不能自行激活自己的结论。
- 无关文件修改不再让精确证据记忆失效。
- 记忆具有来源、时间、冲突和效果数据。

代价：

- 主模型必须可靠调用工具，专项 Agent 测评需要覆盖“只口头答应但未写入”的失败。
- 没有向量通道时，完全没有词面重叠的语义召回仍可能漏掉。
- 便携快照适合有界本地规模，不适合无限聊天归档。

## 约束和验收

- 记忆服务失败不能阻断普通任务。
- 无关任务不得注入项目记忆。
- 当前代码、测试、工具结果和用户本次指令优先。
- 用户可以查看来源、证据、当前状态和使用效果，并能彻底删除。
- 固定逻辑测试与 Agent 能力测评分开；能力测评至少覆盖用户偏好、项目事实、经历、方法和安全五类代表样例。
- 在引入向量或图通道前，必须比较 Recall@5、误召回率、任务成功率、额外 Token、额外延迟和有害记忆率。
