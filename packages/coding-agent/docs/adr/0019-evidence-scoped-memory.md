# ADR 0019：长期记忆必须绑定证据、作用域和生命周期

- 状态：Proposed
- 日期：2026-08-09
- 影响范围：coding-agent 的上下文、记忆、Skill、项目规则、存储和用户界面

## 背景

把历史会话或自动总结直接注入后续任务，可以减少重复探索，但也会放大旧结论、提示注入和隐私泄漏。路径相同不代表仓库相同；同一仓库的不同分支、worktree 和版本也可能有冲突事实。删除原记录后，索引、摘要和候选中还可能残留派生内容。

因此，记忆不能只是“一段文本加相似度”，而必须回答：来自哪里、在哪个范围有效、最后何时验证、派生出什么、现在是否仍可信。

## 决策

1. 记忆分为工作、用户、项目、经历和方法五类，拥有不同的默认加载策略。
2. 自动提取只产生候选记忆；用户指令、权限和 Skill 不能被不可信内容直接改写。
3. 项目记忆绑定规范化仓库身份、分支/worktree、版本和文件指纹。
4. 当前用户指令、当前文件和当前验证结果在相同事实范围内覆盖历史记忆；仓库文本无权覆盖用户偏好、权限或安全策略。
5. 记录保存来源可信等级、派生关系、敏感等级、有效期、记录版本和内容摘要。
6. 精确路径、符号和关键词检索优先；语义检索是有超时和 Token 预算的可选加速器。
7. 常驻上下文只包含小型、明确批准的用户与项目摘要；其他记忆按任务取回有限条目。
8. 编辑使用版本比较；多会话冲突不能由最后写入者静默覆盖。
9. “忘记”沿派生关系删除或失效摘要、索引、候选和缓存，并向用户说明备份保留期限。
10. 记忆不可存储 API Key、认证令牌或可直接使用的秘密。

## 原因

- 来源和版本可以判断一条知识是否已经过期。
- 候选机制阻止网页、仓库注释和模型幻觉静默进入长期规则。
- 分层召回比注入全部历史更节省 Token，也更不容易干扰当前任务。
- 派生关系使修改、撤回和隐私删除真正可执行。
- 版本比较适配多个 Pi 会话同时工作的实际情况。

## 备选方案

### 方案 A：保存全部聊天并做向量搜索

实现直观，但隐私、Token、提示注入和过期知识风险最高，因此拒绝作为默认方案。

### 方案 B：只维护 AGENTS.md 和 Skill

可审查且容易共享，但不能保存个人偏好、临时经历和自动失效信息，因此保留为稳定团队知识出口，而不是唯一记忆层。

### 方案 C：只存模型自动总结

成本较低，但总结会丢失证据并把推测固化为事实，因此拒绝。

## 结果

正面影响：

- 记忆更准确、可解释、可撤销。
- 无关任务几乎不增加 Token。
- 能在代码变化和分支切换后自动降低旧记忆权重。
- 用户能看到并管理系统“记住了什么”。

代价：

- 数据模型、失效检测和删除逻辑更复杂。
- 有些记忆需要用户确认，学习速度会变慢。
- 仓库重写历史或大量移动文件时，需要重新验证。

## 约束

- 记忆服务故障不能阻断普通任务。
- 记忆不能自行授予工具权限或批准候选。
- 不可信来源的原文不能作为系统指令执行。
- 存储必须有配额、原子写入、迁移和损坏隔离。
- 导出前必须再次执行秘密扫描和脱敏。
