# ADR 0034：统一主代理能力平台

- 状态：Accepted
- 日期：2026-08-10
- 影响范围：coding-agent 的结构化编辑、LSP、DAP、文件工具、资源读取、MCP、ACP、插件和审批

## 背景

Pi-go 已有搜索、锚点编辑、基础 LSP、基础 DAP、网页工具、扩展系统和评测闭环，但部分能力仍以独立扩展堆叠：写操作的预览方式不同，Windows 工具仍可能依赖外部程序，文件与网页读取入口分裂，外部工具协议还没有接入统一权限模型。

继续逐个增加工具名称会扩大提示词、配置和维护成本，却不能保证任务成功率。主代理真正需要的是一条稳定链路：找准代码、正确修改、运行验证、失败时快速降级。

## 决策

采用“统一能力契约 + 可替换后端 + 单一审批面”的架构。

```text
模型工具 / RPC / ACP
        ↓
工具适配层：短 schema、中文/英文说明、结果上限
        ↓
能力服务层：计划、预览、执行、回滚、诊断
        ↓
后端层：Node 原生 / LSP / DAP / MCP / 可选外部程序
        ↓
统一控制：路径边界、审批、取消、审计、自动验证
```

具体决策：

1. `ast_edit` 作为所有批量结构化修改的基准：先得到完整计划和 Diff，校验文件版本，再逐文件原子替换；失败时回滚。
2. LSP 对外提供 15 个明确操作。高频操作使用稳定字段；受限原始请求只允许语言服务器协议，不允许任意进程或网络地址。
3. Windows 的 grep、find、ls 和文件扫描优先使用进程内实现；外部 `rg` 只作为可选加速器，不再是可用性的前提。
4. Shell 继续支持用户真实环境，但执行器选择必须显式：通用命令优先已配置 Git Bash，Windows 专属命令使用 PowerShell；二者不可用时返回一次清晰错误，不进入重试循环。
5. DAP 共享一个会话管理器，基础读操作与执行控制分级审批；危险的内存写入和任意请求不进入默认工具说明。
6. `read` 使用资源解析器注册表。文件、HTTP(S)、PDF、压缩包和内部协议返回同一种有来源、大小上限和截断信息的结果。
7. MCP 工具必须先转换为本地能力声明，再进入工具审批、超时、取消和输出脱敏；MCP 服务不能绕过宿主策略。
8. ACP 只是同一 AgentSession 的编辑器传输层，不复制第二套代理状态。
9. 插件只组合扩展、Skill、MCP 配置和资源；安装、更新和启用分开，安装前展示来源、能力和文件差异。
10. 不为了对齐 Oh My Pi 的数量引入语音、桌面控制或默认多代理。新增能力必须在现有 Agent 评测中证明价值。

## 非功能要求

- 普通本地 grep 的首批结果应在 200ms 内开始返回；外部程序缺失不能导致 WSL 错误或重复重试。
- 所有长操作支持 `AbortSignal`；取消后不留下临时文件、调试器或 MCP 子进程。
- 工具输出有字符、文件数、匹配数和时间上限；超限返回缩小范围的方法。
- 写操作默认限制在工作区；符号链接、junction 和预览后文件变化必须失败关闭。
- MCP、HTTP 和插件内容一律按不可信输入处理，不能提升权限或读取凭据。
- 可选能力不可用时，主任务必须在一次失败内降级到 read、grep、edit 或明确说明。
- 新能力不增加普通对话的模型调用；发现型工具只在需要时加入活动工具集。

## 结果

正面影响：

- 主代理工具形成一致的预览、执行、取消、审批和验证体验。
- Windows 不再因为 WSL 或 `rg.cmd` 包装器失效而丢失基本搜索能力。
- TUI、RPC 和 ACP 共享同一能力与安全边界。
- 后续增加语言服务器、调试器、资源协议和 MCP 服务时无需重新设计宿主。

代价：

- LSP、DAP 和资源读取的测试矩阵扩大。
- 进程内搜索需要自行维护 ignore、编码、二进制文件和正则边界。
- MCP、ACP 和插件引入新的生命周期与不可信输入边界。

## 备选方案

### 直接复制 Oh My Pi 的 Rust 原生层

性能上限高，但代码体量、平台发布和维护成本过大。先实现稳定进程内基线并测量瓶颈；只有基准证明必要时才引入小型 Rust 模块。

### 每项能力继续做独立扩展

短期快，但会重复审批、缓存、取消、路径解析和错误处理，长期行为不一致，因此拒绝。

### 所有能力继续依赖外部 CLI

实现最少，但 Windows 环境已经反复出现 WSL、Git Bash 和包装器错误，不能作为可靠基础，因此只保留为可选加速或兼容后端。
