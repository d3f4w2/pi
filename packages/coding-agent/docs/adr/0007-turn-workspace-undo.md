# ADR-0007：按代理回合保存工作区快照并安全撤销

## Status

Accepted

## Context

哈希锚点、结构化编辑、LSP 和测试可以减少错误，但不能证明实现方向一定正确。代理可能一次修改多个文件，也可能通过终端命令修改文件。用户发现方向不对时，需要恢复整个代理回合，而不是逐个文件猜测如何还原。

恢复不能覆盖用户在回合结束后继续做的修改，也不能使用 `git reset --hard`、移动分支或清理整个工作区。项目可能在代理开始前已经包含暂存、未暂存和未跟踪文件，这些内容都属于用户，必须原样保留。

## Decision

增加隐藏内置扩展和 `/undo-turn` 命令，采用“回合基线、净变化快照、安全预检、事务恢复”的流程。

```text
agent_start
  ↓
取得项目级独占记录锁
  ↓
Git 基线 + 未跟踪文件基线
  ↓
代理通过任意工具修改项目
  ↓
agent_settled
  ↓
只保存相对基线发生净变化的文件
  ↓
提示：本回合可用 /undo-turn 撤销

/undo-turn
  ↓
展示文件清单并要求确认
  ↓
校验当前文件仍等于回合结束状态
  ↓
准备全部恢复内容
  ↓
事务式恢复；失败则回滚已执行步骤
```

关键规则：

1. Git 项目使用 `git stash create` 生成不改变工作区的跟踪文件基线；没有跟踪文件变化时使用当前 `HEAD`。
2. 回合开始时单独保存未跟踪、未忽略的普通文件。忽略文件、子模块、项目外路径和超过限制的文件不做部分承诺；遇到它们会放弃本回合快照并提示用户。
3. 快照保存在用户 Pi 配置目录，不写入项目，不加入模型上下文。正常通过时不增加模型 Token。
4. 回合结束后保存每个文件的原内容、结束状态哈希和操作类型：修改、新建、删除。重命名按删除加新建恢复。
5. 撤销只能由用户输入 `/undo-turn` 触发。交互界面必须先展示清单，再弹出确认；无交互界面时拒绝执行。
6. 如果任何当前文件与记录的回合结束哈希不同，视为用户或其他程序后来修改，整次撤销失败，不覆盖任何文件。
7. 恢复前为全部目标准备临时文件；提交过程中保留当前文件备份。任一步失败时按相反顺序恢复，避免留下半恢复状态。
8. 不修改 Git 索引、提交、分支或仓库配置。代理在回合中改变 `HEAD` 时放弃快照并明确提示。
9. 同一项目同时只能有一个 Pi 会话记录快照。另一个活动会话存在时，本回合禁用快照并提示，避免把两个代理的修改混为一谈。
10. 非 Git 项目不声称可以完整追踪终端副作用，因此本版本明确跳过并提示。以后可以增加平台级文件系统隔离，但不降低当前安全边界。
11. 未被用户信任的项目不自动运行 Git 快照命令；完成项目信任后才启用。

## Non-functional Requirements

- 快照初始化不遍历 Git 跟踪文件内容；普通 Git 项目的额外启动延迟目标小于 200 毫秒。
- 单文件上限 5 MiB，单快照总量上限 50 MiB，起始未跟踪文件和候选变化文件分别最多 500 个。
- 每个工作区最多保留 20 个可撤销快照，旧快照按时间清理。
- 所有路径先解析并验证位于仓库根目录内。
- 快照文件使用随机内部名称，清单不把项目相对路径直接当作存储路径。
- 错误必须安全关闭：无法证明能够完整恢复时，不创建“可撤销”承诺。

## Consequences

### Positive

- 一次撤销可以恢复本回合修改、新建、删除和重命名涉及的全部普通文件。
- 用户已有的脏工作区不会被 Git 重置或清理。
- 撤销前后的哈希校验保护用户后续修改。
- 终端命令产生的 Git 可见文件变化也能被捕获。
- 成功路径不增加模型调用或上下文 Token。

### Negative

- 回合开始和结束各需要少量 Git 与文件系统操作。
- 未跟踪文件必须在回合开始时复制，数量或体积过大时会禁用本回合快照。
- 忽略文件、子模块、无提交仓库和非 Git 项目暂不支持完整撤销。
- 进程在多文件提交的极短窗口内崩溃时，可能留下内部临时文件；清单保留恢复证据，但本版本不实现跨进程事务日志重放。

### Neutral

- `/undo-turn` 恢复文件内容，但不撤销会话消息、命令副作用、外部服务操作或 Git 提交历史。
- 撤销完成后工作区可能仍然是脏的，因为它恢复的是代理开始前的真实状态，而不是强制恢复到 `HEAD`。

## Alternatives Considered

**`git reset --hard`**

拒绝。它会删除用户未提交修改，并且会改写整个工作区，而不是只撤销代理本回合。

**每回合自动 `git stash push`**

拒绝。它会移动用户文件、影响索引和 stash 列表，并可能与其他会话冲突。`git stash create` 只生成基线对象，不改变工作区。

**只记录 `edit` 和 `write` 工具**

拒绝作为完整方案。终端、LSP 重命名和扩展工具同样可以修改文件，只监听工具名称会漏报。

**回合开始复制整个项目**

拒绝。大型仓库、依赖目录和二进制文件会显著拖慢每次任务。

**使用 Git worktree 或平台文件系统克隆运行主代理**

暂不采用。隔离最强，但跨平台、终端进程和当前脏工作区合并的复杂度过高；以后可以作为独立安全模式。
