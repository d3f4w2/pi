# 单代理平台实施路线

状态：实施中

日期：2026-08-09

## 实施顺序

顺序不能反过来。先有评测和安全底座，后面才有资格做记忆和自进化。

```text
阶段 0：统一数据与能力定义
  ↓
阶段 1：评测闭环
  ↓
阶段 2：安全能力模型
  ↓
阶段 3：证据型记忆
  ↓
阶段 4：受控自进化
  ↓
阶段 5：统一用户控制台
```

用户体验不是最后才做；每个阶段都要同时补对应界面。阶段 5 负责把所有入口最终统一。

## 当前进度

已完成第一批评测基础：

- `RunRecord` 已记录脱敏的 Token、费用、重试、工具和验证摘要。
- 已定义 `EvalCase`、确定性评分器、`EvalReport` 和基线比较。
- `/evals` 已支持运行、查看、保存基线、比较和查看失败。
- 已提供 10 个完全离线的基础设施冒烟案例。
- 代理可以从已恢复的真实错误提出最小回归测试，但制作和写入分别需要用户批准。
- 回归候选必须具有“失败后修改代码并验证通过”的运行证据，并通过真实产品代码触达质量门。

这些案例只证明评测链路能够稳定工作。下一步仍是建立真实开发任务集、候选不可写控制目录和隐藏保留集；记忆与自进化尚未开始实施。

阶段 0 会先建立评测所需的最小进程外边界：临时工作区、默认禁网、无生产凭据、候选不可写控制目录。阶段 2 再把同一能力模型扩展到所有日常工具。没有这层最小隔离，阶段 1 不能运行自动生成的候选。

## 阶段 0：打地基

目标：统一后续功能依赖的数据，不再让每个扩展各自定义状态。

交付物：

- `RunRecord`：运行、工具、耗时、Token、重试、结果证据。
- `EvalTrace`：仅在显式评测中保存可复现的脱敏轨迹，与普通统计分开授权。
- `CapabilityManifest`：工具的文件、命令、网络和凭据能力。
- 威胁模型：明确控制面、数据面、同进程扩展和 RPC 的信任边界。
- 稳定的事件名称、版本号和本地存储迁移机制。
- 隐私分级与统一脱敏器。
- 原子写入、记录版本和多会话冲突处理。
- `/home` 最小状态页，能看见当前功能是否可用。

验收：

- 关闭记录功能不影响任务执行。
- 记录中不出现 API Key、完整环境变量和未授权源码正文。
- 旧数据损坏时可以隔离并恢复启动。
- 关闭评测和学习时不增加模型调用或提示词 Token。
- 两个会话同时修改同一状态时能发现冲突，不静默覆盖。
- 评测候选运行在临时工作区，默认断网、无生产凭据且不能写控制目录。

## 阶段 1：先把评测做实

目标：回答“这次改动到底有没有让代理更好”。

交付物：

- 本地评测目录、清晰的案例格式和候选不可写的控制目录。
- 第一批开发任务和隐藏保留任务，覆盖定位、编辑、修复、测试、网页和故障恢复。
- 确定性评分器：文件结果、测试、类型诊断、禁止动作、资源预算。
- 固定环境摘要、候选内容摘要、基线管理、重复运行、A/B 对比和 Markdown/JSON 报告。
- 不稳定案例隔离、评测数据脱敏、保留期和删除机制。
- 从真实失败制作案例时执行最小化、秘密扫描和许可证/用户授权检查。
- `/evals run`、`/evals compare`、`/evals failures`。
- CI 中只运行快速回归集；完整评测按需运行。

验收：

- 同一版本重复运行能报告波动，而不是只给一次结果。
- 能定位是哪个任务、哪个工具和哪个阶段导致退步。
- 报告同时包含成功率、Token、P50/P95 耗时、工具数、重试和安全违规。
- 模型裁判不能覆盖确定性失败。
- 候选不能修改评分器、保留集、基线或报告。
- 报告展示分布和长尾；10 个冒烟案例不能作为正式推广证据。
- 基线与候选使用相同模型、推理等级、工具 schema、依赖和仓库夹具成对运行。

## 阶段 2：统一安全底座

目标：让所有工具都通过同一套权限和审计规则。

交付物：

- 工具静态能力清单、每次调用的动态能力请求和风险等级。
- 文件路径、命令、网络域名、环境变量的 allow/ask/deny 规则。
- 凭据代理和统一输出脱敏。
- 可选隔离执行后端：宿主机、仅工作区写入、容器/沙箱、禁网。
- 受保护的控制面目录；候选和普通工作区不能修改权限、评分器和批准记录。
- 外部内容来源标记，阻止不可信文本提升权限。
- `/safety` 查看有效规则、来源、最近拒绝和审计记录。
- 安全回归集。

验收：

- 未声明网络能力的工具无法联网。
- 未声明秘密能力的工具看不到供应商 Key。
- 路径越界、命令注入、SSRF 和提示注入测试通过。
- 无人值守模式遇到未知高风险动作会拒绝，而不是默认放行。
- Shell、符号链接/junction、DNS 重绑定、重定向、输出控制字符和资源耗尽测试通过。
- 界面明确说明同进程扩展仍是受信代码，不能把能力声明误称为沙箱。

## 阶段 3：证据型记忆

目标：减少重复探索，但不让过期记忆误导代理。

交付物：

- 工作、用户、项目、经历、方法五类记忆。
- 来源、可信度、时效、仓库版本和文件指纹。
- 小型常驻记忆和按需召回器；精确检索优先，语义检索可选。
- 文件变化触发相关记忆失效。
- 自动总结只进入候选队列。
- 派生关系、级联遗忘、磁盘/Token 配额和多会话版本冲突。
- `/memory` 查看、搜索、添加、批准、编辑、遗忘、导出、诊断。

验收：

- 无相关记忆时，任务 Token 和延迟几乎不增加。
- 记忆服务失败时，主任务快速降级。
- 当前代码与记忆冲突时使用当前代码，并给出失效原因。
- 用户可以找到“这条记忆从哪里来、谁批准、何时验证”。
- 来自网页和仓库的不可信内容不能直接改变权限、用户偏好、项目规则或 Skill。
- “忘记”后相关索引和派生记录也会删除或失效。

## 阶段 4：受控自进化

目标：让代理从真实失败中改进，但不能自行把未经验证的改动投入生产。

交付物：

- 失败聚类和归因器。
- 记忆、提示词、策略、Skill 四类候选生成器。
- 隔离候选工作区和冻结基线。
- 自动 A/B 评测与推广门禁。
- 用户审查差异、批准、拒绝、灰度和回滚。
- 候选、评测、批准和启用之间的内容摘要绑定。
- 影子模式、全局停止开关和低风险灰度范围。
- 失败聚类门槛、生成频率、并发和 Token 预算。
- `/learn proposals`、`/learn test`、`/learn approve`、`/learn rollback`。

验收：

- 没有 EvalReport 的候选无法启用。
- 核心回归成功率不下降，安全违规为 0。
- 每个候选能追溯到失败案例、变更和评测结果。
- 灰度失败会恢复上一个稳定版本。
- 默认不允许候选修改核心代理源代码。
- 候选在批准后发生任何变化都必须重新评测。
- 灰度候选不能发布、删除、付费或使用生产凭据。

## 阶段 5：统一用户控制台

目标：用户不需要记住内部架构，也能控制所有能力。

交付物：

- `/home` 汇总模型、工具、权限、记忆、评测、学习和后台任务。
- `/settings` 使用统一 schema，展示“当前值、来源、影响、恢复默认”。
- 新手、标准、严格、离线四种配置档案。
- 所有耗时动作显示阶段、进度、预计等待、取消和降级选项。
- 错误信息统一为“发生了什么、是否影响任务、下一步怎么办”。
- 配置导入导出和一键诊断。
- 导入配置前做 schema 校验、风险摘要和差异预览，不直接覆盖现有安全策略。
- 窄终端、中文宽字符、长路径和大量列表的响应式测试。

验收：

- 新用户不读文档也能完成模型配置、工具管理和一次安全任务。
- 工具不可用时能直接看到原因和安装方法。
- 用户能在三个操作以内暂停记忆、撤回候选或切换严格安全模式。
- 用户能看见权限和配置的最终值来自哪个文件、会话或命令行参数。

## 第一批实施切片

下一步只做最小但完整的评测基础，不同时开五条战线：

1. 定义 `RunRecord`、`EvalCase`、`EvalReport`。
2. 把现有运行指标接入统一记录，但保持默认低开销。
3. 建立 10 个完全离线、确定性评分的冒烟案例，只验证评测基础设施。
4. 实现候选不可写的评分器、内容摘要和基线对比报告。
5. 给 `/evals` 提供运行、查看和比较三个操作。
6. 写对应架构文档、ADR、测试和 Token/速度基准后再提交。

这 10 个案例通过后，只能说明评测器能稳定工作。要把结果作为功能推广门禁，还需要扩充开发集、隐藏保留集，统计任务波动并确定每类任务所需样本量。

完成这个切片后，后续每个功能都必须先回答：

- 它提升了哪些任务的成功率？
- 是否增加 Token 和延迟？
- 是否引入新的权限或数据风险？
- 失败时如何降级和回滚？

答不出来，就不进入默认能力。
